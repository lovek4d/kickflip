# The server adds reviewers from fetched lists

This extends [the board server removes reviewers itself](2026-11-04-0119-the-board-server-removes-reviewers-itself.md) to adds. That ADR left adds with the session because the server had no Slack token and no way to look people up. [The hub's own Slack token](2026-11-05-0141-the-hub-sends-reviewer-slack-messages-with-its-own-token.md) removes the first reason, and fetched lists remove the second.

- **Board settings picks from two lists.** `GET /api/reviewer-people` answers `{slack, github}`. Slack members come from `users.list` through the hub's Slack token (the `users:read` user scope joins the app manifest). GitHub logins are the board repo's collaborators, fetched with `gh` as the owner. The page lists both side by side; tapping a member and a login (or typing a login) and then Add stages the reviewer, and Add stays off until both are chosen (owner, gh193-add-2). A reviewer row shows the Slack name with `github: <login>` below it and no Slack id.
- **Save writes both.** `reviewers {add: [{name, slack_user, github}], remove: [name]}` goes through `POST /_claude/events`. For each add the server checks the login on GitHub, which gives its own spelling and refuses an unknown one, opens the owner's DM with the member through `conversations.open` (so `dm` is filled, as `store.mjs` requires), and writes through `addReviewers`, which also copies the list to unfinished waves. It then appends `reviewers-removed {remove}` and `reviewers-added {add: [name]}`. Both are record-only events: the session takes no action on them and the watcher prints them on the next wake. Nothing is written when any add is refused.
- **The session is out of it.** There is no reply to wait for, so Save reads "Saved" for adds too. The hub's poll already sends an added reviewer every PR in review ([#35](2026-11-05-0141-the-hub-sends-reviewer-slack-messages-with-its-own-token.md)), so the session sends no Slack link. SKILL.md drops the add step. `board.mjs reviewers add/set --file` stays for scripts.
- **When a list can't be fetched.** With no Slack token, or one Slack refused, the Slack list is empty and the picker shows `SLACK_NEEDS_TOKEN`'s text with a link to Hub settings; a token without `users:read` (Slack `missing_scope`) says to update the app on Hub settings › Slack. No connector or session fallback ([Slack is out of the session](2026-11-05-0141-the-hub-sends-reviewer-slack-messages-with-its-own-token.md)). A GitHub list that fails to load leaves typed logins working, with the reason shown.

Considered:
- a name a subagent resolves to both ids: slower, and it needs the session this change removes;
- a free-typed Slack id: nothing checks it, and the picker already has the members' names.
