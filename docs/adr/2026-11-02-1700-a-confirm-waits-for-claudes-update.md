# A confirm waits for Claude's update

The owner asked on hub/INT-257 why a pick with a note opened "Is this it?" straight away: "it should only come after a selection is finalized with a note that requires confirmation". A note usually asks for a change, so the confirm the board opened at once showed the take before Claude had changed it. They wanted this enforced in code, not in the skill's wording. This amends [a prototype round ends with a one-take confirm](2026-11-02-1332-a-prototype-round-ends-with-a-one-take-confirm.md) and [a pick with no note settles a prototype round](2026-11-02-1607-a-pick-with-no-note-settles-a-prototype-round.md).

- **A pick with a note opens no confirm.** The board server no longer opens one on an owner answer. The question stays answered, waiting on Claude, so it leaves Needs you, and the topic's head reads "Prototype round N" orange with a spinner while it waits (`domain.mjs` `awaitsConfirm`).
- **Claude opens the confirm.** Once it has updated the take, the session runs `board.mjs question confirm <id> [--url <prototype page>]` (`store.mjs` `confirmQuestion`). It adds "Is this it?" on the same topic and round, offering the take the owner picked alone, on `--url`'s recorded prototype or else the question's own. The take's file must exist there. It resolves the question, noting "Followed by Is this it?", and replaces an open confirm on the topic, as the board's confirm did under [a prototype round ends with a one-take confirm](2026-11-02-1332-a-prototype-round-ends-with-a-one-take-confirm.md). Any answer to the confirm still settles the round.
- **`--no-change` settles a note that changed nothing.** `question resolve` refuses a pick with a note until its confirm is answered, naming `question confirm`. With `--no-change` it resolves the question instead, adding "The note needed no change to take X." to the note and recording the answer it covers in owner.json's `no_change`, which settles the round with that take (`domain.mjs` `roundSettledBy`).
- **A later question doesn't skip the confirm.** `question add` on a card's topic still resolves the card's answered questions, noting "Followed by <id>", but not a pick with a note waiting on its confirm.

A pick with no note still settles the round at once, and a note with no take still resolves its question, as [a pick with no note settles a prototype round](2026-11-02-1607-a-pick-with-no-note-settles-a-prototype-round.md) describes. [A prototype answer with a note gets a confirm round](2026-11-01-1514-a-prototype-answer-with-a-note-gets-a-confirm-round.md)'s building gate is unchanged: it reads the newest answer, so a confirm answered with no note lifts it, and a `--no-change` resolve doesn't.
