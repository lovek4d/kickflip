# Every ask is a task card from the moment it arrives

#486 (hub/T-2). The owner: answering an ask should make it a card that waits in In Review for their Done, and an ask should be a card from the start rather than an ask row the orchestrator turns into one.

This is the successor to [the + makes a New card, which Claude files, folds or answers](2026-10-29-1639-the-plus-makes-a-new-card.md) (itself the successor of every-ask-is-a-card) and to [an ask is titled in place and wears an Ask badge](2026-11-10-1200-an-ask-is-titled-in-place-and-wears-an-ask-badge.md). It supersedes [New shows only on an ask](2026-11-05-1632-new-shows-only-on-an-ask.md) in part: a work card the ask became shows New until it is sorted. It amends [`item add --from-ask` files an ask in one command](2026-11-10-1100-item-add-files-an-ask-in-one-command.md) and [a task is a card with no ticket, keyed T-<n>](2026-11-09-1500-a-task-is-a-card-with-no-ticket-keyed-t-n.md).

- **Arrival.** When the board server takes an `ask` event, it files the card before it writes the event (`store.mjs` `fileAsk`, under the tickets lock): a `T-<n>` item in Todo with `from_ask`, titled from the ask's first line (else its file names), with a notes file headed by that title. The card goes in the first item file there is. A file-items board starts its file; a waves board with no wave keeps the ask as its own New row, since filing never makes a wave. A pass over the board after each change (`fileNewAsks`) files any New ask that has no card yet, so asks from before this, or ones a write missed, get one too. An edit retitles a card still New, and the owner deleting its message drops the card with no Done row.
- **New.** Until it is sorted, the card is `isNew`: it shows its ticket chip like any card (never a New badge), carries the ask's bump, edit and delete icons, and its footer reads "waiting" until the watcher picks it up, then the thinking line. The owner's message is its thread's first line. It waits on the orchestrator as an `intake` wait keyed by the card, and the watcher's line names the card and how to sort it.
- **Sorting.** The orchestrator writes notes (`item notes`) and sets the card's phase (`item set <key> --phase grilling|prototyping`, or `ready --size` for a Quick build ask's card). There is no `--from-ask` step: `item add` and `item set --from-ask` refuse an ask that is already a card, naming it.
- **Answering.** `reply <key>` answers the card: the answer goes in its thread, `answered_at` is set, and the card waits in In Review for the owner's Done, with no Action needed and "Tap Done once it is settled" as its next line. It joins the answer banner. An owner reply there waits on the orchestrator ("Your reply waits on the orchestrator"), as on any In Review card. Setting a phase afterward clears `answered_at` and brings the card back to Todo. `reply <eventId>` on an ask with a card answers the card the same way.
- **Merging.** `item relate-ask` on an ask whose card is still New drops the card: its thread lines move to the ask's thread, followed by a "Merged into <card>." line (`card-merged`), and the ask shows in the other card's thread. The owner's banner names the card it merged into, with a link (`domain.mjs` `merges`). A sorted card refuses the merge.
- **Moving.** `ask move` drops the ask's unstarted cards rather than closing them.
- **Numbers are never reused.** A dropped card's number is kept as the item file's `last_task`, which `nextTaskId` reads.
- **Older asks.** Amended by [old asks migrate into cards, and the ask-only records retire](2026-11-09-2000-old-asks-migrate-into-cards-and-the-ask-only-records-retire.md): an ask handled before this became a card too, an answered one in Done, and no ask draws as its own row; a waves board with no wave refuses the + rather than keep a New row. Old `ask-moved-closed` thread lines keep their wording.
