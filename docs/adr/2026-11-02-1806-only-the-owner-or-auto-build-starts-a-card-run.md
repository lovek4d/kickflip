# Only the owner or Auto-build starts a card run

The owner asked on hub/INT-262 why the iOS board kept building with Auto-build off: "if auto build is on only then should the button be hidden, and find out why it is auto building despite the setting being off. this might be another case of skill describing something that should be programmatic". The board's `auto_build` was off and the hub's tick never fired; the iOS session started each run itself with `board.mjs build <key>`, because SKILL.md let any session request a run and [a device app card carries an Install link](2026-10-29-1729-a-device-app-card-carries-an-install-link.md) told device-app boards to build an install after each push. This supersedes in part [a device app card carries an Install link](2026-10-29-1729-a-device-app-card-carries-an-install-link.md)'s install after each push and [a board's build script serves or builds each card and main](2026-11-01-1846-a-boards-build-script-serves-or-builds-each-card-and-main.md)'s Serve or Build button and `board.mjs build`.

- **Two starters.** A card's run starts from the owner's Serve or Build, or from the hub's Auto-build tick (`hub/try.mjs`). Main's build after each merge is unchanged.
- **The CLI quotes the owner.** `board.mjs build <key>` (and its alias `install`) refuses without `--asked "<the owner's words>"`, as `--confirmed` does for building past a noted pick ([a prototype answer with a note gets a confirm round](2026-11-01-1514-a-prototype-answer-with-a-note-gets-a-confirm-round.md)). The words must appear, ignoring case and runs of whitespace, in an ask, an edit to one, a card message or an answer's note in the board's `data/events.jsonl` (`store.mjs askedGate`). Once the hub starts the run, the card's thread gets "Running at the owner's ask: "<words>"". Board rules don't count: a standing "build each push" is what Auto-build does, so it is the owner's cue to turn Auto-build on.
- **The owner's button skips the CLI.** Serve or Build posts to the board's `POST /api/try`, which forwards to the hub's loopback `POST /_hub/build`, so it needs no quote.
- **Serve or Build shows only while Auto-build is off.** The board snapshot carries `auto_build` to each card's try state as `autoBuild` (`board/domain.mjs`). While it is on, the open card shows no Serve or Build, Retry included; Visit or Install, its stale mark and the failure badge stay.
- **No greyed button on an unchanged branch.** A card whose branch has no commits beyond main shows no Serve or Build, instead of a disabled one explaining there are no changes. On a Todo card that leaves the orange card Build alone at the end of the row ([a Todo card that nothing blocks has Build](2026-11-02-1745-a-todo-card-that-nothing-blocks-has-build.md)). A run going and a current version still show the disabled button with their reason.

Considered:
- a skill rule alone, telling sessions not to request runs: skill text is what built with Auto-build off, so the CLI checks instead;
- refusing `board.mjs build` outright: the owner sometimes asks for a run in words, and quoting them keeps that path open and on the record;
- keeping Retry while Auto-build is on: Auto-build retries at the next head, and the failure badge still opens the log;
- hiding the button through `script` in the try state: `script` says whether the branch has a build script, which the badge and main still need.
