# The try manager settles and takes a runner

Card #657, F4 of docs/test-determinism-audit.md. hub/try.test.mjs waited on the try manager by reading try.json every 20 ms against a 30 s budget, and under that the manager ran its own git with a 3 s limit and the real `ps` and `lsof`. On a loaded host a slow git failed a start or a tick, and a wait could miss a short state altogether (the pull's `running`).

- **`settled()` and `next(key, state)`.** `createTryManager` returns both. `settled()` resolves once every run is ready or has ended and no start, kill, tick, pull, probe, stop or run's end is under way; it counts the work it tracks, so a pull's background tick and a run's close handling (its failure line included) hold it. `next(key, state)` resolves when key's entry next moves into state on any board. It is checked each time try.json is written, so it sees every way an entry moves, `update()` and the direct writes (Main's failure, the base serve's) alike. A test awaits `settled()` after its own start or tick, and `next()` before an event the manager hasn't seen yet, such as a script told to exit.
- **`run` for every command the manager runs.** git, ps, lsof and tailscale go through `run(command, args, options)`, execFile's shape. `fetchTryBranches` takes the same `run`, and the manager's pulls hand `pullBranch` and `resetBranch` a git built on it, so a test's runner reaches every git the poll runs. A test passes a runner that drops time limits, fakes ps and lsof with its own stand-ins, or holds a fetch until it releases it.
- **A local git has no time limit.** The manager's 3 s limit on its local git is gone. That git reads and writes local repos and never waits on the network, so only a slow host made it slow, and there the limit turned a slow tick into a failed one. A fetch from origin keeps its 10 s (`ORIGIN_TIMEOUT_MS`), and ps, lsof and tailscale keep theirs: each guards a call that can hang for a reason other than load.
- **`grace` for a stop.** How long a stopped run's process group has after SIGTERM before SIGKILL is an option, 4 s by default as before.
- **The probe interval stays real.** The 250 ms port probe isn't put under `t.mock.timers`: mocking `setInterval` would also stop `endGroup`'s check that the group is gone, so a stop would never end. A test awaits the probe's outcome with `settled()` or `next()`, and the probe running every 250 ms changes only how long it takes.

hub/try.test.mjs now awaits these instead of polling. Each script's own signal reaches the test through a unix socket the script connects to; a socket's close tells the test the process holding it has ended. What's left on the guard's count for the file: the hub-route test, which runs a real hub until F2, and F8's three test-side clean-ups.
