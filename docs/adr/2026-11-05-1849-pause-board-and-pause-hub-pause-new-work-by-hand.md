# Pause board and Pause hub pause new work by hand

The owner asked (hub #355) for a switch at the top of the settings that pauses new work "in the same way that a usage buffer pauses work, exactly the same", per board as well as hub-wide, manual, with the snooze time box for its end.

- **Pause hub** is the first row of Hub settings; **Pause board** heads Board settings. Both use the snooze picker (hub-kit.js `durationPicker`, shared now with Board settings): 1h, 3h, 6h, 1d and Custom, without Forever, since the ask is a temporary pause and a forgotten one would hold work with nothing to end it. While on, the row reads "Paused until <time>" with Resume.
- The ends live where their scope does: settings.json's `paused_until` for the hub (`setHubPause`, `POST /_hub/settings/hub-pause`), board.json's `paused_until` for a board (store.mjs `setBoardPause`, the board server's `POST /api/pause`). Pause board is no board setting: no `settings` event, no `setting` line; the gate tells the session.
- `shared/usage-gate.mjs` stays the one gate. `readUsageGate({dir})` reads a board's own pause with the board's site dir; without it, only the hub's. A pause in force returns `{state: 'paused', manual: 'hub' | 'board', window: null, used: null, resets_at: <end>}`, so every consumer of the usage pause (builder start, the tap's refusals, the board server's pulls, planners, landers, rebases and held launches, the architecture review, the watcher's held events, the hub's session wakes, the hook) runs the same logic. Every board-side reader passes its dir; the hook finds its board as the manifest site whose owner session is the hook's session.
- Precedence: Pause hub, then Pause board, then the usage pause. Keep going lifts only the usage window, so it never lifts a manual pause. A manual pause holds Codex builders too (`heldFor`), since it pauses all new work, where the line only hands Codex's share to Claude.
- Ending: the hub's tick sees Pause hub lift as it sees a usage pause lift and sends every board `usage-resumed {window: "manual"}`. A board's server sends its own session `usage-resumed {window: "manual"}` when its Pause board lifts with nothing else pausing.
- Words: the hook says "The owner paused the hub" or "this board"; refusals say "Work is paused: the owner paused … until <end>. Pause hub in Hub settings (Pause board in Board settings) resumes it."; the watcher prints `usage paused <end> manual hub|board`.
- Display, gray as every paused status (docs/adr/2026-11-05-1200-waiting-and-paused-read-gray.md): Pause hub fills the Hub banner, with Resume in place of Keep going, the Hub row and every board, as the usage pause does. Pause board shows only on that board: the sidebar data carries a paused board's own gate as its site's `pause`, which its sidebar row and its view (header, card and thread lines) read in place of the hub's.
