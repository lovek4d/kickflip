# An answer stops waiting once it's acted on, and a Next set during the card's questions clears

This extends [an answered question stops waiting once Claude acts on its card](2026-11-01-1813-an-answered-question-stops-waiting-once-claude-acts-on-its-card.md), which resolves an answered question when the session acts on its card, to the owner's answer lines, and fills a gap in [an In Progress card always has a builder line or a Next](2026-11-03-0237-an-in-progress-card-always-has-a-builder-line-or-a-next.md).

**An answer is acted on.** An owner answer's line in a card's thread drops "Waiting for Claude…" (state `answered`) once its question is resolved at or after the answer (no `resolved_at` counts too), once a later prototype round names its question (`round_of`), or once a build starts on the card after it: a builder record of any kind but grill or prototype started later (`board/domain.mjs` `threadOf`). A reply or a later Claude line still answers it as before. The questions page reads the same resolution from `ownerQuestion`'s `acted` on each answer. A batch of answers in a row still carries one marker, under its last answer, but only answers in the same state batch, so an acted-on answer never hides an earlier one still waiting (`board/public/ui-threads.js`).

**A Next that waited on questions clears.** A `--next` written by `item set` or `builder done` while the card has an open question marks the wave entry `next_on_questions`. That Next, and the mark, are cleared once a build starts on the card (`builder start` of a building kind, or `item set --status building` without a new `--next`), or once a step that acts on the card's answers (`question resolve`, a `reply`, `item set --notes-file` or `--status building`, `builder start`) leaves none of the card's questions unresolved (`board/store.mjs` `clearWaitedNext`). The card then reads its builder line, or "Next: none set yet" as [an In Progress card always has a builder line or a Next](2026-11-03-0237-an-in-progress-card-always-has-a-builder-line-or-a-next.md)'s gap. A Next set with no open question is left alone.

On kickflip.sh #1 every prototype answer kept reading "Waiting for Claude…" after its round was built and the card went to PR #2: the line cleared only on a `reply` to the answer's event, which acting as the skill describes never writes. A builder's `builder done --next "Owner picks a tagline on #1"` stayed on the card after the pick and the build.

Considered:
- recording the ids of the questions a Next waited on, clearing it once those resolve: a later round on the same card resolves its earlier question while the owner still has to pick, so the card's open questions as a whole decide;
- clearing every Next on a build start: a Next not about the questions, such as one waiting on CI, would go with it;
- a session step that replies to each acted-on answer: sessions forget steps, which is how this happened ([the CLI and board server do the board's housekeeping](2026-11-02-2044-the-cli-and-board-server-do-the-boards-housekeeping.md)).
