# A land runs its repo's own test script

Every land, PR push, nightly run and builder `board.mjs test` ran `node --test` only. A repo with no `*.test.mjs` files got an ok run of zero tests, so a Swift, Python or static-site repo landed untested. The owner asked on T-502 for a land to run the repo's own tests (T-514), and answered its grill on 11/21. Amends [a board's scripts live in its repo or in kickflip](2026-11-17-1451-a-boards-scripts-live-in-its-repo-or-in-kickflip.md), whose scope becomes build, `build-<target>`, release and test, and [builders run only their own tests and the land runs the affected set once](2026-11-14-0600-builders-run-only-their-own-tests-and-the-land-runs-affected-once.md).

- **Where it lives.** As the release script does: the run's executable `.kickflip/test` on a board whose scripts are in the repo, or the site's `scripts/test` on a board whose scripts are in kickflip (`build-script.mjs scriptFileOf`). Owner: "This should do the same as the build scripts, allow in repo or internal." `board.mjs script set test` writes the kickflip copy, and Board Settings shows a `test` code box after `release`.
- **One chooser.** `worktree.mjs repoRun({home, base})` is the runTests of the land (`prepareLand`), the PR push (finish.mjs `sendForReview`) and the nightly suite (hub/nightly-suite.mjs): the test script when there is one; else the node tests (the affected set with a base, every file with none); else a refusal. T-502's one-at-a-time bound wraps it unchanged.
- **Run whole, handed the base.** The script runs with no shell, the worktree as cwd, and the base as its one argument (`main`, or `refs/remotes/origin/<base>` for a PR push), so it may narrow itself. The nightly suite hands it nothing, since it runs main against itself: no argument means run everything.
- **Bounds.** The 15-minute cut-off, background priority and process-group kill of the node run (`inGroup`, shared with `nodeTests`); raise it when a repo needs it. A run cut off refuses as hung, naming the script.
- **A failure just refuses.** The refusal shows its exit and last 20 lines and saves the whole output to the logs. It names no test file, so it is never rerun on the base ([a land reruns an untouched failing test on main](2026-11-14-1530-a-land-reruns-an-untouched-failing-test-on-main.md) stays node's).
- **No tests refuses.** A repo with no test script and no `*.test.mjs` file refuses: "no test command for <repo>: add an executable .kickflip/test, handed the base; one that exits 0 lands untested" (or `board.mjs script set test` for a kickflip board). A stub that exits 0 opts out, in either home. Every pass says the script's last line, in the land's output and the card's thread line, so a stub's "no tests here" shows on each land.
- **The builder runs it too.** In a repo with a test script, `board.mjs test` runs it whole, handed the base, so its failures show in the build, not first at the land (orchestrator, 11/16). With none it runs the node test files the change adds or edits, as before.
- **The build script checks apply.** A test script that `buildScriptError` refuses (not executable, writable by others, not the owner's) is refused by name, not run.

Considered:
- A free-text test command in board settings: turned down as a build command was ([Board Settings picks which build script a board runs](2026-11-05-1823-board-settings-picks-which-build-script-a-board-runs.md)); a script is reviewed like code.
- Detecting the command (Package.swift, pyproject, package.json): rejected for an explicit script, so nothing changes what runs behind the owner's back.
- Landing an untested repo with a red line instead of refusing: the owner chose refuse, with a stub to opt out.
- Rerunning a failing script on the base: the owner chose "just refuse".
