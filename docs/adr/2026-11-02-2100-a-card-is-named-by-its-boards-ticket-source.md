# A card is named by its board's ticket source

hub/INT-273: the hub board files its cards as GitHub issues, yet its cards read `INT-269` while their issue is `#27`, because the session picked every card id by hand and an internal wave's label was its id. The owner settled that a card's name comes from the board's ticket source, and kickflip, not the session, picks a new card's id. This builds on [a board has one ticket source](2026-11-01-1348-a-board-has-one-ticket-source.md) and supersedes in part [the hub board files its cards as GitHub issues](2026-11-02-1611-the-hub-board-files-its-cards-as-github-issues.md).

- **The label follows the source.** A card's label (`ref`, `board/domain.mjs` `refOf`) is its stored ticket when that ticket is from the board's source: `#27` on a GitHub board, `ENG-12` on a Linear board, `PREFIX-n` on an Internal one. A card without such a ticket keeps its old label: an internal wave's `S<n>` reads `PREFIX-n`, anything else its id. A board without a source reads as before. Board cards, notes headers, blocked-by chips, lineup orders, question pushes and the CLI's and watcher's one-liners (`store.mjs` `cardName`) all take the label.
- **Keys don't move.** A card's key (`hub/INT-269`) stays as stored, since branches, worktrees, threads, builder records and notes files use it. Only its label changes. Text in threads still links the stored id to its card, and a bare `#n` that is a card's ticket opens that card from any thread.
- **`item add <wave>` names the card.** Without an id, `item add` makes or links the ticket first and takes its id from it: the ticket itself, or `GH-<n>` for issue `#n`, since an id names files and branches. It prints `<label> added as <key>`, and the session uses that key. A Linear board without Hub's key can't make the issue, so the add is refused with the MCP line to create it and run `item add <wave>/<id> --ticket <id>`. An explicit id still works, for imports.

Considered: keeping the board's own numbering (`INT-275`) for new keys while only the label followed the ticket. The owner wanted the session to stop choosing ids and the card named from its ticket, so the id comes from the ticket too.
