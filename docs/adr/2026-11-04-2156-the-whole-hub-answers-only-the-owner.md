# The whole hub answers only the owner

Since #200 only restarts and the permission switches checked who was asking; every other hub path, board and try port answered any tailnet device. A shared-in user or tagged node could read every card, answer questions, add cards, upload files and start builds (a board's /api/try reaches the hub's loopback /_hub/build, so the hub saw a local call). The owner's answers on #210 (gate-all-notes.md, "The build") settled a gate at the front door.

- **One gate before routing, on plain requests and upgrades (owner, gh210-read-only: owner only).** `board/on-host.mjs` `ownerGate` decides `owner`, `other` or `unread`; `hub/hub.mjs` asks it for every request before anything else, and in `server.on('upgrade')`, which skips the request handler. The owner is the same as #200's (docs/adr/2026-11-04-0502-only-the-signed-in-owner-changes-permissions-or-restarts.md): a client address that is one of the Mac's own (the Mac's browser, and every loopback caller: the CLI, builders, hooks, push.mjs, the hub's calls to boards), or a `Tailscale-User-Login` equal to the Mac's tailnet user. No login header (a tagged node, Funnel) is `other`.
- **The owner's login is read once and kept (owner, gh210-no-tailscale: keep once read; until read, refuse and say why).** Every request, asset, poll and stream now passes the gate, so `tailscale status --json` runs only until it names the user; the gate keeps that user for the hub's lifetime. A failed read is kept for 5 seconds before tailscale is asked again, so a missing CLI doesn't spawn on every request. Until read, a signed-in request is `unread`: a 503 page, "Tailscale didn’t answer, so this kickflip can’t tell who you are." and "Open it on the Mac itself, or try again in a moment.", or 503 `{error}` for an API call. The Mac's own browser and loopback callers never need the read. A re-login as another user locks the phone out until the hub restarts.
- **Everyone else gets prototype take B (owner, gh210-refusal-look: B).** `hub/front-door.mjs` answers a request that accepts HTML with the skateboard mark, "This kickflip belongs to someone else." and a gray "Ask its owner to share it with you." as a 403, the same for every path and naming no board, title, route or owner; anything else gets a 403 with `{}`. The mark and colours are inline, since `/_hub/kickflip.png` and `/_hub/colors.css` are refused too. An upgrade gets the same status and JSON body on its socket.
- **Try ports pass the same gate, and builds are told to listen on loopback (owner, gh210-try-ports: gate the relay and pass HOST).** `tailscale serve --https=<port>` proxies HTTP to the card's relay, so the relay is now an HTTP proxy (`http.createServer`) that asks the hub's gate for each request and upgrade before passing it to the app. `.kickflip/build` runs with `HOST=127.0.0.1`, and SKILL.md asks a website script to listen on it. An app that ignores it and listens on every interface stays reachable by address and port; kickflip doesn't choose its bind.
- **#200's own checks are gone.** With nobody but the owner reaching the hub or a board (board servers listen on 127.0.0.1 and only the hub forwards to them), `/_hub/restart-board`'s and `/_hub/restart-hub`'s 403 and `/api/permissions`' `owner` field, with its disabled switches and "Only the signed-in owner can change these.", could never fire, so they were removed.
- **Sharing is its own card.** The owner asked for a board-level share setting naming a Tailscale identity; this gate admits only the owner's login.
