# A board's session wakes when an event arrives, and live means its session runs

Claude Code stops a background session that has finished its turn and been unattached for about an hour, and no setting turns that off. Board sessions are left to stop that way. When an event lands for a board whose owner session isn't running, the hub resumes that session at once, records the id it comes back under, and tells it to rejoin with that id and relaunch its watcher. A board counts as listening only while its owner session runs and a watcher runs for it (`isListening` in `hub/boards.mjs`). A board whose session isn't running but the hub can wake is asleep; any other board that isn't listening is deaf, which nothing will wake (`listenState`). The In Review header, the sidebar, the hub links' events link and the not-listening push all read that one state, and the wake reads `isListening`.

The owner picked waking on the event (`idle-boards` on hub/INT-134), after Backend Audit and Shipyard stopped idle in the background: Shipyard's watcher outlived its session, so its board read listening with nobody behind it, and resuming both with `claude --resume <id> --bg` and the hub's flags started copies under new ids that `web-ts resume` never recorded.

- **How the hub notices.** Every 15 seconds `checkSessions` counts each board's watched lines. When it first sees a board's owner session not running it keeps those counts as the outage's `mark` in `~/.claude/web-ts/resume-state.json`; a count past the mark is an event that landed with nobody listening, and the session is resumed then. The outage keeps one resume, so a second event waits for the first wake to come back or to fail. A board not listening for 3 minutes whose session hasn't heard an event past its watcher cursor is resumed as the fallback, which covers events from before the hub was counting. A board with nothing waiting stays stopped.
- **How it resumes.** A background session (one `claude agents --json --all` lists as `background`) gets `claude --resume <id> --bg <prompt>` with no other flags: Claude Code wakes it in place, under the same id and with the options it started with. With any flag it starts a copy under a new id and says so on a `note:` line, which is how the copies happened. A session that never ran in the background gets the hub's flags (name, auto mode, settings, model) and keeps its id. Either way the hub reads the id from `backgrounded · <short id>` and the session records, and records it as the board's owner, keeping label, model and folder.
- **`claude respawn <id>` isn't used.** It restarts a stopped background session under the same id, but idle: it takes no prompt, so the session wouldn't rejoin or relaunch its watcher.
- **The cursor goes back to the mark.** A watcher left running after its session stopped can print an event to nobody and move its cursor past it. The wake winds the session's cursor back to the mark, and gives a new id the old one's, so its first watcher prints every event since the session stopped.
- **A woken session keeps its start's settings.** Since a background session resumes with no flags, a change to `BG_SETTINGS` (`hub/sessions.mjs`), such as the prompt hook of [a background session's prompts and questions come to the phone](2026-10-30-1516-background-sessions-prompts-come-to-the-phone.md), reaches a board only through a new `web-ts start`.
- **An asleep board is calm; a deaf one is red.** Since every quiet board's session stops within an hour, reading each one as broken would turn the sidebar red every evening (owner, `idle-board-status` on hub/INT-133). A board is asleep while its owner session isn't running, a session and folder are recorded, and no wake of this outage has failed or gone unanswered (`error` or `pushed_at` in its resume-state entry). It reads a muted Asleep in the sidebar, its events link passes, the In Review header shows its time as usual, and it gets no not-listening push: a failed wake pushes on its own. It is deaf, and reads the red Not listening, with no session or folder recorded, after a wake fails or goes unanswered, or while its session runs with no watcher.
- **join keeps the record.** A rejoin that leaves out `--label`, `--model` or `--repo` keeps the owner record's, whether the same session rejoins or one takes over with `--force`. A watcher still running for the old id prints `handed-over`.

Considered:
- `claude respawn` then a prompt: there is no command that sends a running background session a message.
- Pinning board sessions so they never idle out: memory pressure still stops them, and the owner chose to let them stop.
- Keeping the watcher as the sign of listening: a watcher outlives its session, which hid Shipyard's outage.
- The 3-minute resume for every board that isn't listening: it would resume each session minutes after it idles out, undoing the stop.
