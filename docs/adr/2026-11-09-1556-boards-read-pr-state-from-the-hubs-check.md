# Boards read PR state from the hub's check

A board server read each PR on its cards itself: `gh pr view` and `gh api …/pulls/<n>/comments` per PR, whenever the board was read and the entry was older than 45 seconds. Its own minute tick reads the board, so every PR cost about 120 REST calls an hour on each board that showed it, with or without an open page, Done cards included. At about 40 PRs on one Mac that spends GitHub's 5,000-an-hour REST limit (#457). The hub's check already reads every card PR in one GraphQL query ([the hub checks every minute while you're here, every 5 when away](2026-11-04-0226-the-hub-checks-every-minute-while-youre-here-and-every-5-when-away.md)).

- **The board makes no gh call for a PR.** `board/server.mjs` `snapshot` reads each PR's summary from `~/.claude/kickflip/github-state.json`, which the hub's check writes (`hub/github.mjs` `summarize`), and `prViewOf` picks what the badges and lanes draw. `prState`, `ghPR`, `ghCodexOpen` and the 45-second cache are gone. The board sees a new check on its own minute tick, which re-reads the board.
- **The query carries the badges.** `hub/pr-report.mjs` `PR_QUERY_FIELDS` adds `url`, `mergedAt`, `headRefName`, `updatedAt` and each latest review's author. `reportOf` and `summarize` keep them, with the full head, the CI counts (`checksOf`, the rule the board used), each reviewer's latest state by login, and the open Codex count. A Codex finding is still a top-level review comment by a codex login that no comment replies to, counted from the review threads the query already brought.
- **A new PR waits for the next check.** Until the hub has checked it, a PR has no summary and its card draws no badges. The owner chose that over a one-off gh read (gh479-new-pr).
- **Done and archived cards.** `github-state.json` keeps each PR's last summary, and the hub stops checking a Done card's PRs, so a Done card keeps drawing the state its merge was recorded with. An archived card reads none and draws what it kept (`board/store.mjs` `keptPRs`, [a card's PR badges stay once added](2026-11-06-1547-a-cards-pr-badges-stay-once-added.md)).
- **Quiet hours count as away.** The owner on #457: "every 45 seconds is a lot. should be every minute at most… also overnight polling should be down to 5 min". In quiet hours (`settings.json` `quiet`, 10:00pm to 8:00am by default) the check runs every 5 minutes, or 15 on a low budget, present or not, and coming back doesn't check at once (`hub/schedule.mjs` `nextCheckAt` with `quiet`, `hub/hub.mjs` `nextPollAt`, `presenceChanged`).
- **Left as it is.** `hub/incoming.mjs` still lists each auto-review board's open PRs with `gh pr list` on each check (gh479-incoming). The reviewer picker, tickets, repos, merge and PR creation keep their REST calls; #480 gates them.

Superseded in part by [quiet hours leave the GitHub check's cadence](2026-11-10-1347-quiet-hours-leave-the-github-checks-cadence.md): the "Quiet hours count as away" bullet no longer holds.
