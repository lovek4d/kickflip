# The board shows GitHub checks and Claude's activity, with one refresh

Superseded in part by [kickflip owns the reviewer record](2026-11-01-2347-kickflip-owns-the-reviewer-record.md): the board no longer reads monitor.json to expose an unused wave watched flag; its GitHub check and session watcher health remain.

Superseded in part by [colour says who's waiting](2026-11-01-1817-colour-says-whos-waiting.md): "not listening" in the header is red, a fault.

Below 900px the shared header is a bottom bar; on desktop it stays at the top ([phone headers sit at the bottom, with boards nearest the thumb](2026-10-31-1532-phone-headers-sit-at-the-bottom.md)). The board header is one row, vertically centered: the hub icon, the title (cut with an ellipsis when narrow), then at the right end a short muted time ("now", "3 min", "2 h"), the time since the page last got a change signal or a manual refresh ([the board reloads on a change signal](2026-10-29-1639-the-board-reloads-on-a-change-signal.md)), followed by the ↻ button, in the GitHub line's order (INT-37, INT-54), then the Settings icon, one even gap apart (owner, card INT-55). Those controls paint disabled and dimmed, with refresh spinning, and turn on together once the first board load has answered or failed, the last visit's board painted meanwhile counting as no load ([the board opens on the last visit](2026-10-29-1639-the-board-opens-on-the-last-visit.md)); refresh stays usable offline (owner, cards INT-55 and INT-62; `headerControls` in `board/public/ui-header.js`). Every page's header renders through one seam, `BoardUI.header` in `board/public/ui-page-header.js`: a lead (the kickflip icon toggling the sidebar, or the back arrow with a phone-only logo beside it), the title, then the controls, or a page's own trail such as the questions page's progress (owner, card INT-67). The hub home, hub Settings, each board and each board's Settings all show the same time, ↻ and gear, painting disabled the same way, and only the gear's target differs, hub Settings on the hub's pages and the board's Settings on a board's (owner, card INT-59). The Improvements bulb that sat before the gear is gone ([hub changes come as asks, not Improvements rounds](2026-10-29-1639-hub-changes-come-as-asks-not-improvement-rounds.md)). On those pages other than the board, the time is when the view last fetched its data, and ↻ fetches it again ([one app for the whole hub](2026-10-29-2005-one-app-for-the-whole-hub.md)). When a board load fails, the 30 s poll's included, its time and ↻ turn red, keeping the last time (or reading "offline" when there is none) (owner ask, card INT-64); a lost stream alone doesn't. Offline, the Settings icon is disabled and dimmed, the + button is hidden, and known content, the last visit's board included, stays lightly dimmed and takes no taps except ↻, under a toast reading "Offline, ↻ to retry" that stays until the board is back (INT-80); a ↻ tap retries the load at once, reading "Reconnecting…" until it answers or fails, and sends no `check-github`. A load that succeeds brings everything back (INT-35). The In Review lane's header ends, right-aligned, with the GitHub mark, the same short time as the header ("4 min"), and its own ↻, shown even while the lane is folded. Before a board's first check it reads "not checked", with the ↻, so a new board can ask for one (owner ask, card INT-94). The mark is GitHub's filled logo, the one exception to the line icons of [icons are SF Symbol-style line icons](2026-10-29-1639-icons-are-sf-symbol-style-line-icons.md), since GitHub's logo guidelines forbid altering it.

- **GitHub** is when GitHub was last checked. The hub writes `data/checked.json` `{at, every}` on each poll, with `every` the polling interval's current minutes ([the hub polls GitHub and sends pushes on one polling interval](2026-10-29-1639-the-hub-polls-github-and-sends-pushes-on-one-interval.md)), and the session runs `board.mjs --site <route> checked --every <minutes>` at the end of each monitor tick. With no `checked.json`, it doesn't show. It turns orange, the building color, and adds "checks are late" when the last check is more than twice `every` old. When the board shows no open PR ([one board registry for every hub feature](2026-10-29-1639-one-board-registry-for-every-hub-feature.md); before it, when no waves were watched), the hub's poll and the session's `checked --idle` write `{at, every: null, idle: true}`: the line stays muted and reads only the time after the mark, such as "4 min", never late, and its ↻ still asks for a check. The next plain `checked --every` clears idle (owner, round `site-v19`, option B).
- **Not listening**: the header's time reads "not listening", in orange, when the board is deaf: it isn't listening (its owner session isn't running, or its watcher is stopped) and the hub can't wake it. An asleep board, whose stopped session the hub wakes on the next event, shows its time as usual (`checks.watcher`, from `hub/boards.mjs` `listenState`; [a board's session wakes when an event arrives, and live means its session runs](2026-10-30-1601-a-boards-session-wakes-when-an-event-arrives.md)).
- **Refresh** reloads the board and open threads, dimmed, disabled and spinning while that reload runs (no spin under Reduce Motion). It never asks for a GitHub check (owner ask, 2026-10-23). The GitHub line's own ↻ is the only ask: a tap sends one `check-github {}` event whenever none is pending, which wakes the session to run one monitor tick ending with `board.mjs checked`, with no cooldown, and the ↻ spins and rests (dimmed, `aria-disabled`) from the tap until a check lands after it, so a pending request is the only debounce (INT-44). The In Review header reads "Checking…" after the mark meanwhile, and a tap on either ↻ sends nothing more. A request no check answers stops showing after 5 minutes.

`bin/wait-events.mjs` writes `data/watcher.json` `{pid, since}` when it starts, and adds `exited_at` when it exits. The hub counts the watcher as running while that pid is alive and `ps` shows it running `wait-events.mjs`, since a stopped watcher's pid can be reused by another process. The watcher exits on each event and the session relaunches it a few seconds later, so the board counts it stopped only when none runs and the last one exited more than 2 minutes ago, or left no exit time (it was killed), or there is no `watcher.json` at all.

GitHub is polled because it can't reach the tailnet. A quiet board looked the same whether the last check was a minute ago or the Mac had slept, and the owner had no way to ask for a check.

Considered:
- GitHub webhooks through Tailscale Funnel, which would expose a public endpoint;
- a warning only when checks stop (round `site-v13`, option B);
- no check time at all;
- a separate "Checked GitHub" line under a page-load stamp;
- "GitHub … · Claude …" together in the header (INT-24's first take).

The owner chose to keep polling and show both checks on the board (round `site-v13`, question `v13-last-checked`, option A, and question `int18-polling`), for the gap between watchers not to read as stopped (INT-20), for one refresh that also checks GitHub (INT-24), and for the GitHub time on the In Review header (owner ask on INT-24).
