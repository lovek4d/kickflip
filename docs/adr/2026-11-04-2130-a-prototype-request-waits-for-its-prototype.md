# A prototype request waits for its prototype

The owner, on #46: "why was a prototype not created for this? Make a work item for making sure that prototypes actually create a prototype." On #46 the owner tapped a question's eye with a question in the note; the session answered the question in the thread and drew nothing, and the question had already resolved as "Prototype requested" with nothing behind it (#207). This supersedes the resolution part of [a question asked for a prototype is resolved, and the page moves on](2026-11-03-1803-a-question-asked-for-a-prototype-is-resolved.md); the page still moves on as a Send does.

- **The request no longer resolves its question.** The board server records `prototype-request {key?, question, note, choice}` and leaves owner.json alone. `domain.mjs` `ownerQuestion` reads the question as `requested` while its newest request is newer than its last answer, and it isn't resolved. An answer after the request reopens it as answered, as before.
- **Only the round resolves it.** `question add` with `round_of` naming it resolves it, "Followed by prototype round N", as before. `question resolve` refuses a requested question and says so. The store reads prototype requests beside answers (`store.mjs` `ownerEvents`), so `question add`'s follow-ups and the noTakePicked gate see the same state as the board.
- **Waiting on you shows it locked.** A requested question reads "prototype requested" with the spinner, its options locked at the pick the request sent, the request's note under them, and no note box or eye. It sends nothing, counts as neither open nor answered, and its topic waits only on Claude.
- **A request left waiting is raised.** `domain.mjs` `prototypeWaits` lists each open card's prototype requests still waiting while no prototype agent runs on the card: the card's own request while it's under way, and each question reading requested. The board server's minute check appends `prototype-overdue {key, request, question?, since}` for each one older than 30 minutes (`PROTOTYPE_WAIT`), once per request (the event log says which went out, so a restart sends none twice). The session dispatches the prototype agent on it; #214's wait list covers waking a sleeping board.

Considered: writing a `requested_at` mark into owner.json so store-side readers see it without the event log. Reading prototype requests from the log beside answers keeps one source, as answers already do.
