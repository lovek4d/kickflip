# The orchestrator stops the board's own runs, and a bump orders the land queue

Card #290. On 11/05 frozen test runs held the host's test slot and lands without the fix queued ahead of the top-priority card. Each time the orchestrator had to ask the owner to run `kill <pids>`, since its session can't kill processes. Owner's answers on the card (11/06): all recommendations, and take B of the prototype, "land stopped by orchestrator, consistent copy, dry if possible".

## Decision

- **Only what the board launched, by card.** `board.mjs builder stop <key>` stops the card's headless builder, lander or rebase run: the agent the board server launched, by the pid and time on its builder record's session, checked against the process's start time so a reused pid is never signalled. `board.mjs land stop <key>` stops the card's land, found by its `~/.claude/kickflip/landing/<card>` marker, now `{pid, at, merge?}`. A grill or prototype planner, a builder a session started itself, and a land run in such a session are refused.
- **A stop takes every process under the run.** `headless.mjs stopRuns` reads the process table once and stops each process group holding the run's process or one descended from it, so a land's suite, which runs detached in a group of its own (`worktree.mjs nodeTests`), goes with it: SIGTERM to each group, SIGKILL to what still runs after 5 seconds. It never signals its own group or group 1. It prints each process it stopped. Finding the suite by parent pid at stop time needs no record of the suite's group.
- **A land a headless builder or lander runs stops that whole agent**, since stopping only its `builder done` would leave the agent running done again. The land a held card's Merge tap started (`finish.mjs landHeld`, marked `merge` on its marker) stops alone. A land holding the land lock is fast-forwarding main and restarting servers, so it is refused rather than stopped partway.
- **Nothing relaunches a stopped run.** The stop marks each open build record `stopped {run, at}`, written before the signal. The card reads the stop until a build starts on the record again. The server's revive hands such a build back (`handedBack`, no line of its own), and `launchLanders` neither sends its lander back to checking nor relaunches it.
- **The card stays where it falls, with one status word.** A stopped build or lander stays In Progress, waiting on the orchestrator (a `stalled` wait from the stop's time), its status line "build stopped by orchestrator" or "land stopped by orchestrator" (land while its last status line was the landing phase), plain, with no dot and no nudge. A stopped Merge land leaves the land queue. Its card is back In Review with Merge, reading "land stopped by orchestrator" (`merge_ready.stopped`) until the next tap. One function, `domain.mjs stoppedWords`, makes the words, and each stop writes the same words as the card's thread line.
- **The bump decides the land queue.** A queued land's ticket now holds `{card, site, key, first}`. The queue runs bumped lands first, the latest bump ahead, then the rest by ask time. A land queues with its card's standing bump (`store.mjs landFirst`, read as the board reads a bump). A bump made later moves its queued tickets: the orchestrator's `board.mjs item bump|unbump <key>`, and the owner's bump icon through the server. A waiter also wakes when its own ticket is moved. A bump never stops the land holding the lock. The orchestrator's bump of a queued land writes "land moved first by orchestrator" in its thread. `board.mjs land queue` lists the queue.

## Not done

- No test queue and no `test-slot release`: the host test slot is gone ([land suites run side by side, under a time limit](2026-11-05-0725-land-suites-run-side-by-side-under-a-time-limit.md)), so the land queue is the only queue.
- No board view of the land queue and no owner Stop button. The thread line and the status word are what the card shows (owner, `gh290-card-shows`).
- The bump icon still shows only on Todo and In Progress cards. A bump on an In Review card, which only the orchestrator can make, orders its land without showing on the card.
- The 30-minute push to the owner for a card waiting on the orchestrator stays. It covers an orchestrator that is down or stuck, which its own scan can't catch.
