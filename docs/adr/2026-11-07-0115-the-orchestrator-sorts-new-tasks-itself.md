# The orchestrator sorts new tasks itself

Card #411. Supersedes [intake triage sorts new tasks on Sonnet](2026-11-06-0204-intake-triage-sorts-new-tasks-on-sonnet.md), [a hung intake run times out and hands its ask to the orchestrator](2026-11-06-1200-a-hung-intake-run-times-out-and-hands-its-ask-to-the-orchestrator.md) and [the intake launch line names only the agent and its job](2026-11-07-1600-intake-launch-line-names-only-agent-and-job.md), and the intake parts of [an intake run folds into one section, and every fold ends at its status](2026-11-10-1100-an-intake-run-folds-into-one-section-and-every-fold-ends-at-its-status.md), [a run's fold ends with a log link](2026-11-07-1500-a-runs-fold-ends-with-a-log-link.md) and [server tests turn intake off](2026-11-09-1000-server-tests-turn-intake-off-and-a-pause-marks-the-board-at-once.md).

The owner (11/06): "i think we should actually drop the triage agent entirely. just have the orchestrator take on new tasks and asks. that way if it is processed into a quick build item, the orchestrator can go straight to ready and skip staging. staging should only be for responses to open questions."

## Decision

- **No intake run.** The board server launches nothing for a new task (`ask`), the owner's message in an ask's thread (`item-message` keyed `ask:<id>`) or an agent-added card (`card-added`). Gone: server.mjs `sortIntake`/`runIntake` and data/intake-runs.json, headless.mjs `intakeBrief`/`launchIntake`, domain.mjs `intakeDue`, `intakeHung`, `intakeStranded`, `INTAKE_TIMEOUT_AFTER` and `INTAKE_AGENT`, store.mjs `intakeHandoff` and `board.mjs intake handoff`, the `intake` field on thread lines and its fold, and `KICKFLIP_INTAKE`. Old `intake-handoff` events, intake-runs.json files and intake thread lines stay as history; an old intake line now shows as a plain status line.
- **Those events wake the session again** (gh411-wake), each with an action line (bin/event-lines.mjs), and the watcher marks the ask and the message working as it prints them. Every unsorted intake event is also an `intake` wait on the orchestrator's list (domain.mjs `intakeWaits`), from its event's time and picked up once the watcher marks that event working: "Sort the new task", "Answer the owner's message in the ask's thread", or "Link and file the card an agent added". Like every wait, one left 30 minutes unpicked pushes the owner once. With no session running, a new task waits, as every wait does; the intake run's usage and busy-Mac holds go with it, since the session is itself what a usage pause stops.
- **A New card reads a grey "waiting", its dot still, until the orchestrator picks it up, then the blue "thinking"** (owner note on gh411-wake).
- **A Quick build ask goes straight to ready** (gh411-ready-scope, gh411-related folding #381). The orchestrator's filing is the judgment staging would ask for, so `item add --from-ask <id> --phase ready` on a Quick build ask needs `--size` and `--notes` or `--notes-from`, and `item set --from-ask <id> --phase ready` takes it from any Todo phase, with the usual ready checks (size, notes, answered questions). Nothing files a card in staging any more: `--phase staging` is refused on every ask, reverting #317's gh317-quick and #386's one-write staging. An agent's follow-up still lands grilling or prototyping.
- **Staging stays for every owner reply on an existing card** (gh411-staging-scope): an answer Send, Implement with text, and Reply on a ready card stage it as before. Only the cards the orchestrator files itself skip it.
- #404 is moot: its intake fold goes with the run.

Rejected: keep the run and let it file Quick builds ready (the owner wants one sorter); wake the session without an intake wait (a busy session would lose the task); skip staging for every card the orchestrator files (agents' follow-ups still get their grill).

Superseded in part by [a new task is triaged in one command before it is investigated](2026-11-15-0730-a-new-task-is-triaged-in-one-command-before-it-is-investigated.md): the intake wait asks for item triage first, and a waiting New strip entry reads a grey "triaging" in place of "waiting…".
