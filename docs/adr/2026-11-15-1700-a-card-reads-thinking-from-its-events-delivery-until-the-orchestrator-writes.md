# A card reads thinking from its event's delivery until the orchestrator writes

On T-432 the owner's note (09:28:01) arrived while the orchestrator was posting a question about their earlier message (09:28:2x). The post read as an answer to a note it hadn't seen: any orchestrator line after an owner message counted as answering it, and ended the owner's-last-word wait, however early. Nothing on the board said which message the orchestrator was on.

**Delivery is stamped.** `data/delivered.json` `{since, events: {<event id>: ts}}` records when each event was first handed to the session (store.mjs `markDelivered`): by the watcher (bin/wait-events.mjs) for every event it wakes the session for, and by the PostToolUse hook (hooks-plugin/hooks/board-messages.mjs) for each owner word it shows mid-task. A record-only line isn't stamped: it asks nothing of the session, and a stamped tap would read thinking with no write to end it. `since` is the board's first stamp: an event sent before it counts as handed when sent, so threads from before the change read as they did.

The stamps are kept per event, not per card as the card's notes put it: the card's events are already mapped to it by domain.mjs (`cardOf`, an owner's answer by its question's topic, an ask by the card it became), so the watcher needs no card mapping, and each message keeps its own handover time, which a per-card latest stamp loses once a later event arrives.

**A line answers only what was handed over** (domain.mjs `handedAt`). An owner message is answered by an orchestrator line, a reply or a command on the card (acted-on.json) written after its handover, not after its send. Not handed over yet, it reads waiting whatever the orchestrator writes meanwhile; handed over, thinking. The card's close still answers it, by the owner's tap or the orchestrator's. The owner's-last-word wait (`ownerWordOf`) holds on the same rule, its pickup is the message's handover rather than the first write after it, and the wait's end logged to `limbo-waits.jsonl` names the first line after the handover.

**The card thinks** from the first handover of any of its events after the orchestrator's last write on it (a thread line that answers the owner, a command, the card's close) until its next one (`buildBoard`, `workingSince`): an owner's answer or a request as well as a thread message. A bump and a script run don't (`WRITES_NOTHING`): their plain lines ask the session to write nothing, so the card would think until some unrelated write. Its status line reads thinking… counting from then, in place of waiting for orchestrator or orchestrator review while it lasts (ui-cards.js `orchestratorStatus`); with no wait it reads the same line. Not listening, or an idle session, still reads waiting (`withHub`).
