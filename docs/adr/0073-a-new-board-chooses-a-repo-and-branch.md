# A new board chooses a repo and branch

Superseded in part by [0078](0078-a-pasted-github-link-picks-any-reachable-repo.md): the picker also takes a pasted GitHub link or `owner/name` for a repo outside the list. The list, clones and branches below still hold.

New board starts with the GitHub repo, then its branch and board details. The owner picked take B of `prototype-repo-pick-2.html`: the repo gives the board its starting name and default branch, while the name can change and the purpose is optional. Choosing from accessible repos replaces typing an existing local folder and makes the clone and sharing visible before Start.

The hub lists the owner's and each org's repos through `gh repo list`, after finding the orgs with `gh api user/orgs`, and caches that inventory for a minute. The list sorts newest push first and searches owner, repo and description. Each row shows visibility, last push, clone status and the boards sharing it. A signed-out picker names `gh auth login` and can check again. Branches come from the paginated GitHub API.

Start reserves the route and answers without waiting for cloning or Claude. The sidebar reads Cloning, then Starting. A repo has one clone at `<kickflip clone>/.repos/<owner>/<repo>`, with case-insensitive identity. Concurrent starts take the same renewable directory lock. The hub clones into a temporary directory inside `.repos` and renames the finished clone into place; failure removes the temporary tree. Reusing a clone requires a real `.git` directory, a Git work-tree root equal to the clone folder, and an origin that normalizes to the selected GitHub repo. A mismatched folder is refused and left untouched. Under the clone lock, preparing a new or reused clone fetches the selected branch into its remote ref and refuses a branch absent from the remote. It never checks out or switches branches. The session starts in that clone with the same background settings as [0069](0069-the-hub-starts-a-new-boards-session.md), and a clone or session failure makes the Starting row dismissible.

The Starting record carries `github`, `branch` and the clone path. Joining transfers the repo and branch into the board's manifest entry, including when the session joins before its start result is recorded. Builders get separate worktrees from the board's remote branch, fetched again as each worktree is made. Boards without `github` keep using local `main` of the kickflip clone, including locally landed changes. Boards that have `github` use it for PR polling, the board snapshot's PR state and card links, and install repo lookup, ahead of wave data or the legacy fallback. On hub startup, a one-time `board-github` migration derives missing identities from each existing board session folder's GitHub origin, or its site folder when no session folder is recorded, and records the remote's default branch, else the checked-out branch. It skips the hub board, whose builders work on the kickflip clone.

Board Settings shows Repo and branch and opens the same picker to change them. Saving prepares the selected clone, updates the manifest and the session's recorded folder, and sends `repo-changed {github, branch, repo, previous}` to the board. New builders use the new selection; existing worktrees remain independent. The hub board's Repo row shows kickflip's own clone with no Change, and `POST /_hub/board-repo/<route>` refuses it, since its builders branch from that clone's `main`.

Repo identities and branches are validated. Clone paths reject symlinks through `.repos`, owner or repo and stay inside `.repos`. GitHub and clone commands use one injectable argv runner with no shell; tests stub that runner. New board and repo changes are behind the shared cross-site guard and require JSON. The hub server owns every step, with no dependency on the dev-time hub session ([0068](0068-the-hub-session-is-a-dev-time-role.md)).
