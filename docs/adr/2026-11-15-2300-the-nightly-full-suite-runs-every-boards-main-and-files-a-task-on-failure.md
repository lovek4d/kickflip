# The nightly full suite runs every board's main and files a task on failure

#798 (T-378), split from T-268. The owner (11/14): overnight work starts together at the middle of quiet hours; "Every board's main; a failure files a card". [Lands and builders run only the tests a change affects](2026-11-12-2104-lands-and-builders-run-only-the-tests-a-change-affects.md) left the full run to a nightly job. This is that job.

- **When.** Once a night, from the middle of quiet hours (`schedule.mjs` quietMiddleOf, 3:00am by default) until they end. The night is the calendar day of that middle. `~/.claude/kickflip/suite-state.json` keeps it, written as the run starts, so a hub restart in the middle of a run never starts a second one that night.
- **A row in Overnight work.** "Nightly full suite" (`overnight.mjs` JOBS, id `suite`), on by default. Off, nothing runs. Its last run reads ok, "failed on <routes>" and "couldn't run on <routes>". The red result links the first task it filed.
- **What runs.** Each board's main, `board-repo.mjs` mainRefOf: the local branch for a board building from its folder, otherwise origin's branch, which the hub's poll fetches. It runs on a detached checkout in a temp folder, removed afterwards (`board/worktree.mjs` onCheckout, shared with failingOnBase), so the folder's own uncommitted changes never count. `nodeTests` runs in full with the land's limits, and saves the output of a failed run to `~/.claude/kickflip/logs`.
- **One at a time.** Boards run in manifest order, one after another. Each waits first until the host isn't busy (`untilHostEases`). Boards on the same repo and ref run once.
- **A failure is a New task.** The failing board gets an `ask` event, the path the router files by. Its first line, "Nightly full suite failed on main at <sha>: N of M tests failed.", is the title. Its body lists up to 10 failures and the saved output's path. The board's orchestrator triages it like any New task. A main that still fails the next night files again; overnight triage folds the duplicate.
- **Its own timer.** The hub checks once a minute on a timer of its own, not the 15-second tick, because a run takes minutes per board. So the tick stays quick, and tests that call `tick()` never start a full run. A hub started with `ticks: false` never runs it.
