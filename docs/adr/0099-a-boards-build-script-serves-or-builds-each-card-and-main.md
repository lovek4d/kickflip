# A board's build script serves or builds each card and main

ADR 0102 supersedes the serving path and `KICKFLIP_BASE`. ADR 0119 supersedes what shutdown and startup do with a build still going.

The owner settled the build-script, script-home, auto-build, serve-limits and try-url questions and confirmed the main bar and card badge in try-builds-confirm A. Every work card and the board's main can have a version to try. One reviewed file in the repo tells the hub how to make it; the owner uses Serve or Build on a card and Auto-build cards in Board Settings.

- **One fixed script.** The hub runs `<worktree>/.kickflip/build <wave>/<id> <worktree>`, or `main` in place of the card key, without a shell, in that worktree. It checks the existing worktree restrictions and requires a regular file, no symlink, inside it, owned by the current user, executable and writable by neither group nor others. The old owner-set `install_script` path and its Settings field go away. `KICKFLIP_BOARD` names the route; `KICKFLIP_BASE` names `/<route>/try/<id>/`.
- **The result decides the kind.** A script that prints exactly `port <n>` on stdout owns a website server in its detached process group. The hub waits up to 60 seconds for its port to answer, then serves it. Exit 0 without a port is an app build: the script publishes the card's install with `item set --install --install-sha`, or main's with `main set --install [--install-sha]` into `data/main.json`. A failed exit, exit before the port answers or a run still going with no port after 60 minutes fails the run. The last finished run decides the board's kind, initially app when any card has an install and web otherwise.
- **The hub owns runs.** `hub/try.mjs` replaces installs.mjs. It writes `data/try.json` atomically only when changed, with main and card states, their starting commits and current card heads, changes beyond main and script presence. Logs replace `data/try/<id>.log`, mode 0600. Runs open no builder record and leave the card in its lane. A failed card run writes one thread message with its exit, any keychain hint and the last five log lines; successful runs write none. Main's failure stays in its state and log.
- **Cards can wait; main stays current.** Auto-build cards is off by default. On, the hub's nonoverlapping 15-second tick starts each changed card once per head, with no repeated failure at that head. Main always builds after each merge regardless of Auto-build. The hub uses the kickflip clone's local main for its own board and the recorded origin branch for another, fetching that branch after each GitHub poll. Main runs in `~/.claude/kickflip/try/<route>-main`, a hub-owned detached worktree. New main runs stop the old server before checking out the tip. Sessions no longer rebuild installs on a GitHub `head` change.
- **One badge, one action.** A ready badge reads Visit ↗ or Install ↗; a stale one reads Visit (stale) ↗ or Install (stale) ↗. Running replaces it with an inert spinner and Serving… or Building…. Failure opens the card's thread. The open card's rightmost workflow button reads Serve or Build, Retry after failure, with an explanation when there are no changes, a run is going or its version is current. A tap confirms then asks the hub through `POST /api/try` and loopback-only `POST /_hub/build`; `board.mjs build` does the same and `install` is its alias. Main is a slim bar above the lanes, showing its repo, branch, commit and age with one badge and no button.
- **Serving belongs to the board.** `/<route>/try/<id>/` and `/<route>/try/main/` proxy HTTP and upgrades directly to the server, outside the app shell and service worker's shell fallback, with the prefix stripped and forwarded. A card server stops after 30 minutes without a proxied request, including upgrades, and can be served again. Main never idles out. Shutdown stops every group; startup clears dead card servers and makes main eligible to serve again. The sidebar stays as it is.

Considered:
- an owner-set script path: the reviewed fixed repo file lets each branch supply its own build steps without a path setting;
- rebuilding through a card's session and builder records: the hub can run and track both app builds and long-lived servers without moving cards between lanes;
- a badge in the board header: the confirmed slim main bar keeps the repo, branch, commit and age together and fits a phone;
- stopping main when Auto-build is off, or capping card servers: main always follows merges, while a 30-minute idle limit bounds unused card servers without a cap.
