# A try build serves on its own Tailscale port

The owner chose a separate HTTPS port on the host’s one Tailscale hostname for each served card and main. A path on the hub’s origin lets a served site act on the hub’s settings and breaks root-absolute links. A port gives the site its own origin and lets it serve at its root. This supersedes [a board's build script serves or builds each card and main](2026-11-01-1846-a-boards-build-script-serves-or-builds-each-card-and-main.md)’s serving path and `KICKFLIP_BASE`; its build script, app installs, badges, main bar and idle limit stay as decided.

- **One port range.** `hub/try.mjs` owns 8500–8599. A card takes the lowest free port across all boards, excluding every recorded main port, and keeps it through a new commit or Retry. Idle stop, a board going away, run exit and hub shutdown release it. Each board’s main takes the lowest free port the first time it serves and records it as top-level `main_port` in `data/try.json`. That reservation stays across merges, stops and restarts, including while the board is closed, so main’s link never changes and no card reuses it. An exhausted range fails the run with a clear message. A served entry records the script’s loopback `port` and public `https` port, including `main.https` while main serves.
- **A tiny relay keeps visits visible.** Once the script’s port answers, the hub opens a TCP relay on `127.0.0.1`, port 0, piping connections to the script’s port. Every connection and data event marks the run visited. Card servers still stop after 30 idle minutes; main never idles out. HTTP upgrades and websockets pass through at TCP level. Stopping a run destroys its connections and closes its relay.
- **The hub adds and removes serving.** After opening the relay it runs `tailscale serve --bg --https=<try port> http://127.0.0.1:<relay port>` with `execFile`, `tailscale` from PATH and a 10-second timeout. Only success makes the run ready. Failure follows the usual run failure path; a card’s thread says it could not open the port and includes Tailscale’s stderr. Every stop removes the mapping with `tailscale serve --https=<try port> off`, also timed out; removal errors are logged without throwing. Shutdown stops every process group and relay.
- **Startup removes stale mappings.** Before any tick starts a run, initialization reads `tailscale serve status --json`, parsing stdout alone since stderr may carry a version warning. It turns off every unowned TCP port in the range. It never touches 443 or any other port outside the range. A missing or failing Tailscale logs a cleanup failure and lets the hub start.
- **Links open the site’s root.** Board data emits a public `port` for web cards and main, with `url` null. The browser builds `https://${location.hostname}:<port>/` for Visit and the main bar. App install URLs keep their existing meaning. The old `/<board>/try/<id>/` HTTP and upgrade proxy, its missing-server page and its shell and service worker exceptions go away. Scripts get `KICKFLIP_BOARD` but no `KICKFLIP_BASE`; sites serve from `/`, and root-absolute links work.
- **Doctor explains the ports.** An informational ok row lists each in-range Tailscale mapping and its board and card or main from `data/try.json`, or none. The hub’s root check reads only 443. On Linux, a non-root hub user must be Tailscale’s operator; doctor compares `tailscale debug prefs`’s `OperatorUser` with the current username and marks a mismatch yours, with `sudo tailscale set --operator=$USER` as the fix.

Considered:
- prefix support through `X-Forwarded-Prefix`: fixes only kickflip’s own pages and keeps the same-origin risk;
- one try port routed by a header: shares an origin between builds and needs a routing header a normal browser Visit cannot supply;
- pointing Tailscale straight at the script’s port: hides requests from the hub and loses the idle limit.
