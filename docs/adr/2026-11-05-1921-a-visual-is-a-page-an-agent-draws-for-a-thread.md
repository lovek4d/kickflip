# A visual is a page an agent draws for a thread

The owner asked to be able to request a visual in a card's thread: a diagram, flow or comparison drawn as a one-off HTML page that answers a question. It is neither a prototype nor a grill, so it asks no question, has no takes and leaves the card's state alone. The grill on #298 settled the shape, and the owner picked take A of the prototype round (gh298-look).

- **Trigger.** An image icon at the end of the thread footer's icons (eye, fire, image) sends `visual-request {key, text?, files?}` at once, with whatever is typed, the way the eye and fire do. `/visual` typed in the box does the same on Reply. With nothing typed, the agent draws what the thread was last discussing. The thread shows the request the way it shows the eye's and fire's: a bare tap is a gray "visual requested" request line led by the image mark, and a tap with text is the owner's message with "visual requested" in its footer.
- **Agent.** The board server launches a headless visual agent on Sonnet (`headless.mjs visualBrief`), in the board's repo. Its record is its own agent on the card, `visual-<request event id>` (`store.mjs startVisual`), so it runs beside any build, grill or prototype. A visual is a planner kind: it writes no code and its agent lines are blue. It is not the card's work, though, so the card's status line skips it (`domain.mjs builderOf`), it doesn't keep a Todo card from arriving for its grill, it doesn't hold back staged questions, and its start resolves no answered question. It does count toward the planner cap.
- **One after another.** `domain.mjs visualsDue` names each card's oldest visual request that no agent has drawn, but only while no visual agent runs on that card. The server launches it on the tap and again on each auto pass. A visual agent's finish writes its record, which triggers an auto pass, and that pass picks up the card's next request. A launch the usage pause holds waits for the pause to lift.
- **Pages.** `board.mjs visual add <key> --file <page.html> --title <t>` copies the page to the site's `public/visuals/<card id>/<slug>.html`. Each request gets a new name, so earlier pages are never overwritten. The command also writes a `visual` thread line linking the page. Pages may load libraries such as Mermaid or D3 from a CDN (gh298-files B). Pages stay after the card closes. Cleaning them up is #357.
- **Showing.** The visual line is a plain link line, "<title> →" with its time. It opens the page in the board's reader sheet, like a prototype (gh298-show C chose full page; [prototypes and visuals open in the reader sheet](2026-11-16-0514-prototypes-and-visuals-open-in-the-reader-sheet.md) moved it). It counts as Claude's answer to the request before it.

Amended by [every planner launches from the orchestrator's brief](2026-11-12-0600-every-planner-launches-from-the-orchestrators-brief.md): a visual request owes the orchestrator a visual brief, the board launches the agent from it, and the agent's record is `visual-<its brief's time in ms>`.
