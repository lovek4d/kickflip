# Each question has the thread's request row

The owner asked on hub/T-406 for a question's prototype eye to sit at the right, beside a visual request, the attach out of the note box "to align more with thread reply", and a grill "to go deeper on a certain question": "Everything but the what's left." Then: "Let's also apply the same to the new task modal." This extends [each question has its own prototype eye](2026-11-02-1822-each-question-has-its-own-prototype-eye.md), whose eye and attach started the note row.

- **One row, three boxes.** `BoardUI.requestIcons(id)` (`board/public/ui.js`) is the Prototype, Grill, Visual and attach, in that order, right-aligned in its row. A card's reply box puts What's left? at its left and its send buttons after it; each open question puts it under its note box, its files at the left (`ui-questions.js` `noteComposer`); the New task box puts it under its text box the same way (`new-task.js`). Each box's text area is a bare drop zone: the attach is on the row, not in the box. The questions sheet, which answers no requests, keeps the attach alone (`requests: false`).
- **A question's Grill and Visual ask about that question.** As Prototype sends `prototype-request {key?, question, note, choice}`, Grill sends `grill-more` and Visual `visual-request` with the same fields (`view-questions.js` `askAbout`). The server already hands a tap's question, note and pick to the card's owed brief (`store.mjs` `planAgain`). The card's thread shows each as the question, the pick and the note under Grill or Visual requested (`domain.mjs` `actionText`), and a question's grill keeps the card grilling until its questions post, a reply comes or its grill finishes, as a card's Grill tap does (`isRequest`).
- **Only Prototype resolves the page's question.** A question asked for a prototype reads requested and the page moves on, as before. One asked for a grill or a visual stays open with its pick and note, and the status line reads Grill requested. or Visual requested.: the grill goes deeper on the question and the visual helps answer it, so the owner still answers it.
- **The New task's icons send the task with its request.** Prototype, Grill or Visual sends the task at once as `ask {text, request: 'prototype' | 'grill' | 'visual'}`, as a thread's do on its card, and `/prototype`, `/grill` or `/visual` in the text does the same on Discuss or Implement (`BoardUI.slashOf`, shared with the thread). A request takes the place of Implement's quick. The server files the card and then owes that kind's brief on it with the task's text and files (`server.mjs`), and the ask's footer reads the request.

Considered: a new `grill-request` event for a question's grill. `grill-more` already carries a card's grill with the owner's text and the server already passes a question to the brief, so a question is one more field on it.
