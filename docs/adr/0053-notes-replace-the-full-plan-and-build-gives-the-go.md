# Notes replace the full plan, and a card awaiting the go shows Build

A card's long write-up is its **Notes**: the owning session's understanding of the task so far, what was asked, what is settled and what is still open. The session rewrites it as the grill settles things, rather than freezing it as a plan, and the thread keeps the short news. When the card's work is ready to start and waits only on the owner's go, the card shows an orange **Build** button beside its Action needed.

- **Notes.** The item names a Markdown file in its wave's folder, set with `board.mjs item set <key> --notes-file <file>`; `--plan` stays an alias, and the file is still stored in the item's `plan`, so wave files and calls written before need no migration. The open card's **Notes** link opens `notes.html?item=<key>`, headed "<ref> notes", from `GET /api/notes`. With no file, the page shows the item's short `notes` text, so notes written before keep showing. The server reads the file under the same checks as before ([0024](0024-a-full-plan-opens-as-a-page-on-the-site.md)). `plan.html?item=` redirects to `notes.html` and `/api/plan` answers as `/api/notes`, since pushes and threads already link them.
- **The card's notes section goes.** The open card no longer shows the `notes` text in a fold of its own; the Notes page holds it.
- **Build.** `item set <key> --await-build` sets the item's `await_build`; `--status building` or `--no-await-build` clears it. The card then gets the owner action `{kind: "build", label: "Build"}` after any open questions, moves to In Review with Action needed and a Needs you line ([0045](0045-the-lane-follows-who-acts-next.md)), and reads "Next: Build". A held card waits on nobody. The Build sits right of Action needed on the card and leads the open card's action row.
- **Starting….** A tap confirms like every card button ([0023](0023-a-card-can-be-held-and-every-card-button-confirms.md)) and sends `card-build {key}`. The button then reads "Starting…", disabled, with no Action needed, while the latest `card-build` is newer than both the card's `status_at` and its newest Claude thread line other than a status line, as Merge reads "Merging…" ([0052](0052-auto-merge-is-a-board-setting-off-by-default.md)). The card counts as In Progress meanwhile.
- **One Build look.** The card's Build and a follow-up's Build ([0034](0034-follow-ups-are-todo-cards-of-their-wave.md)) share `button.build` in `style.css`, filled with `--color-notice`, the builder orange of building cards, in both themes.

A card whose plan waited on the owner showed its full plan and an Action needed chip that only opened its thread, and the owner gave the go in a thread message. The owner didn't need the plan as a fixed document, but did want the session's current understanding, and a one-tap go.

The owner asked, on a card waiting on them: "should not have full plan visible to user of the board anyway, just give me an orange build button in place of action needed", then "full plan can stay actually, but rename it to notes, drop notes section from the main card, and use that to store a so far understanding of the task", then that a card waiting on a build confirmation keeps its Action needed tag (hub/INT-121).

Considered:
- the Build button in place of Action needed, which the owner first asked for, then kept the tag so every card waiting on them reads the same;
- renaming the stored `plan` field to match, which would mean migrating every wave file on read for no change the owner sees.
