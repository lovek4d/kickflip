# A button tap is a status line or a message footer

The owner, on #207 (prototype rounds `request-flags` 1 to 6, round 6 the final look): every button tap shows as a small gray status line, and a tap that carries text or answers shows as a message with that status in its footer: "for prototype or grill, if either of those are requested without a message, we just get the bare status line style. Otherwise, if there is text associated with it, we get a thread message with that text, and then in the footer we get that status item." Also: drop the Prototype and Grill buttons above the thread for a fire beside the eye; new questions as one blue line in the thread; every status icon in one box.

- **The thread composer requests.** The eye asks for a prototype and a fire to its right for a grill. Both are toggles, one at a time, that Send carries with whatever is typed; /prototype or /grill in the text does the same, the word dropped from the text. A hint under the box says what Send posts. They send `prototype-request {key, text?, files?}` or `grill-more {key, text?, files?}`. The card's action row loses Grill and Prototype (`actionButtonOf` has no `grill`). A question's own eye on Waiting on you stays as it was.
- **Bare tap, one gray line.** A request with nothing typed is a muted request line, "prototype requested" or "grill requested", as before.
- **With text, a message.** A request with text or files, and a question's prototype request (its question, pick and note), are the owner's message with `status` set, which the footer draws first, its icon in the mark box. An answer from Waiting on you carries "answers submitted" in its footer, never its own line; a submit of several answers is one message with one footer (docs/adr/2026-11-07-0800-answers-submitted-together-are-one-thread-message.md). "Waiting for Claude…" (or thinking) sits to the right of the status until Claude picks the message up.
- **New questions are a thread line.** (Superseded by [a Questions added line is stored and stays in the thread](2026-11-13-0130-a-questions-added-line-is-stored-and-stays-in-the-thread.md).) The open card's thread shows its open questions asked since it was last seen as one blue planner line, "N new questions", led by a plain question mark a size up from the other icons, linking to the first (`ui-threads.js` `newQuestionsLine`). The card's time line drops its "N new questions" chip; the questions count as one unread message there.
- **One mark box.** Every thread status line's leading mark, the request icons, the dots of builder and agent lines and the question mark, is centred in one 18px box (`.mark`), so the text always starts at the same place.

Since [every reply-box tap shows its line at once and retries in place](2026-11-14-0530-every-reply-box-tap-shows-its-line-at-once-and-retries-in-place.md), a bare tap's line also reads where it is after its time, "· sending…", "· waiting…" or "· thinking…", as a message footer does, and the line shows the moment it is tapped.

Considered: keeping a separate gray "answers submitted" line before the answers' message (round 2). The owner chose the footer, so a tap that carries content is one entry.

A bare Implement tap's line reads "Marked as staging · sending…" from the tap and becomes the board's own "Marked as staging" line when it lands, matched by the tap's sendId (store.mjs `implementAsIs`, which stamps the staging line). There is no "Implementation requested" line: not for a bare Implement, not under a quick ask. The staging line takes its chevron icon. An Implement with text keeps its message, its footer reading "Implement". This completes [an Implement tap reads only "Marked as staging"](2026-11-12-1100-an-implement-tap-reads-only-marked-as-staging.md), which the page's default line had still contradicted.
