# Every planner launches from the orchestrator's brief

Supersedes in part [staging, then ready](2026-11-07-0700-staging-then-ready.md) (`round_at` rounds), [a no-pick prototype answer starts the next round itself](2026-11-12-0100-a-no-pick-prototype-answer-starts-the-next-round-itself.md) and [a new task is a conversation](2026-11-12-0500-a-new-task-is-a-conversation.md) (`item visual`, and a Grill tap starting the round). Amends [every card arriving in Todo is grilled by the board](2026-11-04-2359-every-card-arriving-in-todo-is-grilled-by-the-board.md) and [a visual is a page an agent draws for a thread](2026-11-05-1921-a-visual-is-a-page-an-agent-draws-for-a-thread.md).

On T-161 the owner asked whether a visual was better handled by the orchestrator; it proposed writing a brief that the agent draws from, and the owner: "Yeah I like writing a brief. Honestly maybe same for prototype and grill?" A grill, prototype or visual agent launched cold reads the whole thread and notes and guesses what the discussion settled. The orchestrator already knows.

- **Every launch needs a brief.** A grill, prototype or visual agent launches only from an orchestrator's brief: what the discussion settled, what is still open, what its questions, takes or page should cover, and the files that matter. The agent's own launch prompt starts from it, before the thread and the notes (headless.mjs `orchestratorsBrief`, inside `plannerBrief` and `visualBrief`).
- **Mechanical.** `startPlanner` and `startVisual` (store.mjs) refuse a card with no written brief, and `orchestratorsBrief` throws on a launch without one, so no path starts an agent cold.
- **A card owes a brief.** The item file keeps `briefs: [{kind, at, ask?, brief?}]`. The owner's Grill, Prototype or Visual tap (`planAgain`), a card arriving in Todo with Auto implement on (`launchArrivals`, still capped by Maximum parallel planners, counting cards that owe one), a gate's yes, an answer that picks no take and `item set --phase grilling|prototyping` each add an owed entry, with the owner's text, files, question, note or pick as its `ask`. An owed entry is the orchestrator's `brief` wait: "Write the <kind> brief: item brief <key> --kind <kind> --file <draft.md>, …".
- **`item brief <key> --kind grill|prototype|visual --file <draft.md>`** appends the draft to the card's notes as "Brief for <kind> round N" and writes it onto the entry, owing one first when nothing was owed, so the orchestrator can start any of the three itself. On the next auto pass the board launches the agent from it (`briefsDue`, `launchBriefs`): a grill or prototype on a Todo card with no other planner running, a visual beside anything but another visual. The launch moves the entry onto the agent's record as `brief`, where a hold's resume and a queued launch find it again.
- **Small visuals** the orchestrator may draw itself with `visual add`; anything bigger goes to the agent with a brief. `item visual` is gone.
- **Status words** (owner: "only be preheating while the orchestrator is writing a brief for a grill. There should never ever otherwise be preheating"): the card's status line reads "preheating" (grill), "planning prototype" or "planning visual" while the brief is owed, then "grilling", "prototyping" or "generating visual" once the agent runs, always blue (owner: "Only the status line should show that … And it should always be blue"). A grill planner's own progress lines read "Grilling: <detail>".
- **The footer** stays discussing until the owner taps Grill or Prototype, then reads grilling or prototyping from the tap, through the brief and the agent's run. A visual never changes it. No "Briefing" or turn text shows for a brief.

Considered:
- The orchestrator dispatching the agent itself after writing the brief: the board already launches, counts and resumes planners, and a brief on the card survives a compaction or a restart where a dispatch in the session would not.
- An orange or red status while a brief is owed, as orchestrator work: the owner asked for blue always.
- A cap on brief launches by Maximum parallel planners: the orchestrator writes each brief deliberately, so its launch goes at once; arrivals, which nobody asked for, stay capped.
