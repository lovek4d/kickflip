# The bulb runs an architecture review of the board's repo

The owner asked on hub/INT-59 for "the lightbulb on a given session [to] run /improve-codebase-architecture on the target session's repository, with the hub referencing the hub, data, model, and template itself", and on hub/INT-65 settled "bring back the bulb and use that". This supersedes in part [hub changes come as asks, not Improvements rounds](2026-10-29-1639-hub-changes-come-as-asks-not-improvement-rounds.md): a bulb is back in the board header, for a review, while Improvements rounds stay gone and hub changes still come as asks.

- **Where and what a tap does** (prototype `arch-bulb`, take A). The bulb sits between ↻ and the gear on a board's header, not the hub page's (`BoardUI.header` `bulb`). A tap opens a sheet: the last review, its wave, date, how many findings and how many of them were built, linking its audit card, then "Run a review of <repo>", which confirms. While a review runs, the bulb glows in the notice colour and the sheet links the running audit card.
- **Code starts it.** Run posts `/api/arch-review`. The board server (`board/arch-review.mjs`) picks the target with `hub/board-repo.mjs` `boardRepo`, makes a lineup "Architecture <date>" ([a wave the owner asks for is a lineup of cards](2026-11-02-1202-a-wave-the-owner-asks-for-is-a-lineup-of-cards.md)) whose first card is the audit card, or on a board over `~/.claude/waves` a wave file of its own, starts a builder record on it so it sits in In Progress, writes its first thread line, and appends `arch-review {key, repo, github, branch, wave, lineup, scope?}`, which wakes the session ([a board's session wakes when an event arrives, and live means its session runs](2026-10-30-1601-a-boards-session-wakes-when-an-event-arrives.md)). The session never guesses the repo.
- **One open review per board.** While the newest review's audit card isn't Done, Run answers with that card and the sheet opens it.
- **The hub board's scope.** Its target is the kickflip clone, and `scope` limits the review to `hub/`, `board/`, `shared/`, `CONTEXT.md` and `docs/adr/`, with a read-only look at the live data's shapes: the manifest and each site's wave, owner and event files.
- **The session follows mattpocock/skills.** It reads the SKILL.md files of improve-codebase-architecture, codebase-design, grilling and prototype, since their frontmatter keeps the Skill tool from loading them. The report is the audit card's Notes ([notes replace the full plan, and a card starts on its own](2026-10-29-1816-notes-replace-the-full-plan-and-cards-start-on-their-own.md)), not the skill's temp HTML file and `open`, which never reach the phone. The audit card asks one question per finding: the problem, some possible solutions as options, and Skip ([a card is grilled through its own open questions](2026-10-29-1639-a-card-is-grilled-through-its-own-open-questions.md)). Each finding not skipped becomes a card of the wave after the audit card, from the picked option, and the cards start on their own once the audit card is Done.
- **The skills are a prerequisite kickflip doesn't pin** (`shared/skills.mjs`). `kickflip install` (and `doctor --fix`) adds a missing one with the skills CLI, `npx skills add mattpocock/skills -g -y -a claude-code --skill …`. `kickflip doctor` marks a missing one, or one whose folder no longer matches the source's tree sha recorded in `~/.agents/.skill-lock.json`, as optional with the command that fixes it. While one is missing the review waits and the sheet says why, as features wait on their integrations ([integrations show readiness, and features wait until theirs is ready](2026-11-02-1118-integrations-show-readiness-and-features-wait.md)); the Integrations section stays as it is, since the skills serve one feature and doctor already names them.

Considered:
- Run in board Settings: the owner chose the bulb.
- A tap that goes straight to the confirm (take B): the sheet shows what the last review left first.
- Only one finding picked to explore, as the skill asks: the owner wanted every finding tracked as a question with a Skip.
- Shipping the skills inside kickflip or as a subrepo: kickflip would have to keep them current; the skills CLI already does.
- The session picking the target, or starting the wave itself: code knows the board's repo, and a sleeping session can't make the card the bulb links to.
