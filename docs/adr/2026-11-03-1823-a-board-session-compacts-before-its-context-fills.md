# A board session compacts before its context fills

The owner, on #124: "It looks like this orchestrator went down because it maxed out on context and never autocompacted. … I'm wondering if there's a way we can enforce this or just have the hub automatically compact context for orchestrators that go above 90% or so." On 2026-11-03 the Hub Orchestrator's context reached about 976k of 1M with autocompact off. Its next turns, a handback and a watcher event, failed with "Prompt is too long", so it relaunched no watcher and the board read not listening. It stayed that way for about 10 minutes, until the owner ran `/compact` by hand.

- **Init turns autocompact on.** `kickflip init` and `doctor --fix` set `autoCompactEnabled: true` in `~/.claude/settings.json` when it isn't already true, an explicit `false` included (`bin/install.mjs` `installClaudeSettings`). Claude Code reads the setting there before the older value in `~/.claude.json`. Doctor's setup item `settings.json autoCompactEnabled` reads ok, or fixable while it is off or not set.
- **Context full.** A board is context full when it reads not listening (`hub/boards.mjs` `listenState` `deaf`) and its owner session's last context reading, the one the sidebar shows (#7), is at or over 95% (`hub/usage.mjs` `contextFull`). The reading's age doesn't matter, since a stuck session writes no newer one. The sidebar row reads **context full** in place of not listening.
- **The hub types `/compact` into the hub board's pane, once per fill.** The hub board's session runs in tmux ([boards run in the background, sleep and wake from the page, and the hub board runs in tmux](2026-11-03-0313-boards-run-in-the-background-and-the-hub-board-in-tmux.md)). On each 15-second session check, if that board is context full and its tmux session exists, the hub sends `/compact` and Enter to the pane (`hub/sessions.mjs` `compactFullContexts`). `~/.claude/kickflip/compact-state.json` records the attempt, a failed one too, so it isn't repeated. The record is cleared once the board isn't context full any more, so a later fill compacts again. A background session has no pane, so it gets only the sidebar word and the existing not-listening push.
- **Then it waits.** The hub sends no prompt after `/compact`. The watcher comes back on the session's next turn, when its Stop hook asks for it.

Considered: reading the transcript for "Prompt is too long". Not listening at 95% or more covers the stall without parsing transcripts. Also considered: typing a wake prompt right after `/compact`. That relies on Claude Code queueing typed input while it compacts, which hasn't been checked. Also considered: waiting until the session is idle before typing. A session that isn't listening at 95% is rarely mid-turn, and autocompact, now on, normally compacts before the hub has to.

An idle session past its prompt cache restarts fresh instead ([an idle orchestrator restarts fresh once its prompt cache lapses](2026-11-17-2330-an-idle-orchestrator-restarts-fresh-once-its-prompt-cache-lapses.md)); this covers a full context on a session that isn't listening.
