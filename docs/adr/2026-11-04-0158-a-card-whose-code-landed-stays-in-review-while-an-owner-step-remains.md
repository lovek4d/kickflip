# A card whose code landed stays in review while an owner step remains

Some cards aren't finished when their code lands. #12 (GitHub Actions publishes kickflip to npm) landed, and land moved it to Done, but the owner still had to add the npm trusted publisher and tag a release. Someone had to reopen it by hand.

- **One flag.** `--owner-step "<text>"` goes on `builder done` and on `land`, whichever finishes the card. It is stored as the item's `owner_step`. `builder done --owner-step` on a card that is already done, merged or dropped is refused, because its ticket has already moved: the step goes on the command that finishes the card.
- **It waits in In Review.** Once the code lands (status done or merged, or its PR merged), a card with an owner step goes to In Review, not Done (`board/domain.mjs` `workItem`). It waits on the owner, with the step as its Next. While the PR is still open, the card waits on that PR as usual. A reopened card that Claude has answered reads its step in place of "Tap Done once it is settled".
- **The ticket stays open.** While the step remains, a done or merged status doesn't move the card's ticket (`board/store.mjs` `changeItem`).
- **The owner's Done closes it.** The owner's Done deletes `owner_step`. A merged card keeps its merged status (`recordOwnerTap`), and its ticket moves to Done. A session's `item set --status done` keeps the step. Dropping a card deletes it. A passing code check on the step closes it the same way ([an owner step can carry a code check](2026-11-04-2308-an-owner-step-can-carry-a-code-check.md)).
- **How it looks.** The step is the card's Next, in the owner-only orange tone. Done is an orange check icon where the bump arrow sits (`board/public/ui-cards.js`), and the card can't be bumped. Like any card that waits only to be closed, it has no Action needed ([a card waiting only to be closed has no Action needed](2026-11-03-0137-a-card-waiting-only-to-be-closed-has-no-action-needed.md)). The owner picked this look, take A of the owner-step prototype: "Maybe done can be a check that is in place of where the bump arrow usually is for in-progress and to-do items."
- **A draft PR names its wait.** A card on a draft PR with no Next reads "Review draft PR #N" (`board/domain.mjs`), so it never reads "none set yet" while it waits on the owner. A Next the card was given wins, and a green draft still asks for Ready on GitHub. This is derived from the PR state the board polls, not written by `item set --pr`, because the CLI doesn't read GitHub when it adds a PR. Owner: "It should just say review draft PR, like rather than this whole thing."
