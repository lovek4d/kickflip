# Each board reviews incoming PRs that touch its work, in an Auto Review lane

Superseded in part by [auto implement fills In Progress up to Maximum parallel implementers, on every board change](2026-11-04-0057-auto-implement-fills-in-progress-up-to-a-cap.md): the review is sent from the check that runs on every board change and at start, not each minute; it still waits for an idle board and for any pulled card to start. The Auto section's first switch reads "Auto implement Todo cards", with Maximum parallel implementers after it.

The owner asked on #117 for each board's orchestrator to "pick up any incoming PRs automatically that relate to that orchestrators work", so teammates' local Claudes form a review mesh "escalating to human only if needed", behind a board setting, with the auto settings collapsed into one section. A grill and two prototype rounds settled it.

- **The hub picks; the session judges.** With a board's `auto_review` on, the hub's poll (`hub/incoming.mjs`, after its GitHub check) lists the repo's open PRs and writes `data/incoming.json {at, repo, prs}` with each non-draft PR from someone else that touches a file one of the board's cards changed, or that asks the owner for review, naming the cards it touches. A card's files come from its PR: an open one from the same listing, a merged one read once and kept in `~/.claude/kickflip/incoming-files.json`, since its files never change. Only boards with a repo on GitHub are looked at.
- **One wake at a time, only when idle.** The board server's minute check sends `pr-review {pr, head, repo, title, author, url, touches, asked}` for the next listed PR no review covers at its head, asked ones first, after triage and any pull, and only while the board is idle as for the pull ([an idle board pulls in its top Todo card](2026-11-02-1754-an-idle-board-pulls-in-its-top-todo-card.md)) and Claude is under the pause line; `pr-review` joins the events the hub holds until reset ([work pauses at the pause line](2026-11-01-1710-work-pauses-at-the-pause-line.md)). A PR it was sent for reads reviewing until the session records a review at that head, and nothing else is sent meanwhile; the event log is the marker, so a restart sends nothing twice. A new head on a posted PR is owed a review again; one held for the owner is not.
- **The session's part.** It reads the PR and the reviews already on it, then posts one GitHub review as Comment only, under the owner's gh login, with a first line naming the board and a hidden marker, adding only points no other review made, or posts nothing. It checks the PR's reviews again right before posting. It holds the review for the owner instead when it finds a blocker, disagrees with a decision on a card, or the PR clashes with a card in progress. `board.mjs review record <pr> --state posted|needs --text|--file [--url]` writes `data/reviews.json`, keeping the PR's title, author and cards after it leaves the listing.
- **The lane.** "Auto Review" leads the board's lanes while the setting is on, or while a review is live: one card per PR with its number, title, author, the cards it touches and its state, lowercase: needs you, reviewing, posted. A tap opens the review text and the PR's links. A posted review whose PR left the listing, or that is over a day old, is a line under "Posted earlier". An empty lane says what was checked and when, or how many PRs wait for the board to be idle.
- **Needs you.** A held review is a Needs you line that opens its card, and pushes the owner once, tagged `review-<number>` with the other owner actions ([the board records what it knows, and commands make the rule calls](2026-11-03-0003-the-board-records-what-it-knows-and-commands-make-the-rule-calls.md)). Its card offers Post it and Skip, which send `review-answer {pr, answer}` and stay off until the server answers; the review reads reviewing until the session records it again.
- **One Auto section.** Board settings' Merging, Builds and Todo headings become one Auto section: Pull in Todo cards, Auto-build cards, Auto review, Auto-merge, then Triage Todo when idle, each a short label with a one-line helper. Auto review is off by default and its helper says it may use a lot of usage; turning it off is how the owner stops the usage.

Considered:
- a separate Reviews view: the owner picked a lane on the board, so held reviews sit beside the work they touch;
- the hub sending the wake straight from its poll: the board server already knows when the board is idle and holds the pull the same way;
- a review per push to a PR regardless of the last one: one review per board per PR head bounds it, and a held one waits for the owner;
- Auto review's own options under its toggle (gh117-layout): none was settled, so it has none yet.
