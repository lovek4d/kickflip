# Kickflip runs from a clone linked into Claude Code's skills

Superseded in part by [0084](0084-kickflip-is-the-only-name.md): the skill link, hooks link and state folder are named kickflip, and install moves this Mac's `~/.claude/web-ts` folder once, leaving a link at the old path.

Superseded in part by [0093](0093-the-hub-runs-under-the-hosts-service-manager.md): install sets up the hub's service for the host, the login item on macOS or a systemd user unit on Linux.

Superseded in part by [0101](0101-kickflip-ships-as-a-minified-npm-package.md): hosts install the minified npm package, which install links in place of a clone, and board repos live in ~/.claude/kickflip/repos outside a clone.

Kickflip is cloned into any folder, for example `~/dev/kickflip`, and that clone is the code that runs. The owner chose this layout in `install-layout`: `web-ts install` links `~/.claude/skills/join-web-ts` to the running clone and `~/.claude/skills/web-ts-hooks` through `join-web-ts/hooks-plugin/`, then installs the hub's login item and Tailscale mapping. This gives a new Mac an install path and keeps the Git checkout independent of Claude Code's skill discovery. No copy of the code is installed elsewhere.

Install checks both destinations before creating either link. An existing real directory is kept only when its realpath is the intended target itself; any other real directory or file is refused. Correct links are kept, including relative links and hooks links pointing directly at the current clone. New hooks links go through `join-web-ts`, so repointing that one link also moves the plugin. An existing hooks link pointing directly at the clone must also be repointed when the clone moves. Wrong or dangling links are refused with a message telling the owner to remove that link explicitly before retrying, even with `--force`. Refusing rather than automatically retargeting a link avoids silently switching a running installation to another checkout. The link function accepts the home directory, skills directory and clone root, and can run alone without launchd or Tailscale.

Board repos belong in `<clone>/.repos/<owner>/<repo>`, with `reposDir()` in `shared/repos.mjs` owning `<clone>/.repos` for the repo picker. That directory is gitignored. Land's test discovery skips `.repos/` and `node_modules/` at every depth, so a board's checked-out project cannot become part of kickflip's suite. The repo picker clones through a temporary directory inside `.repos` and reuses one clone per repo, guarded by a renewable lock ([0073](0073-a-new-board-chooses-a-repo-and-branch.md)); installing kickflip creates no board repos.

Live state stays in `~/.claude/web-ts/`, including the manifest, sites, settings and builder worktrees. Paths used while code runs resolve from the running modules, and builder and land defaults use the running clone. Node resolves symlinked main modules to their real paths, so commands work both from the clone and through the installed link. Every absolute path saved for later use inside the kickflip clone names `~/.claude/skills/join-web-ts` instead, when that link resolves to the running clone; a worktree, or a scratch HOME without the link, keeps real paths. `storedPath()` in `bin/install.mjs` owns that conversion, preserving paths outside the clone and relative paths. It covers manifest commands, site and session folders (including board repos under `.repos` and closed boards), session hook settings and prompts, builder worktree records, board item files, install scripts and the hub's login item. The hooks plugin also names the link. Moving the clone and pointing the link at its new folder keeps those paths working without rewriting saved state or the plist. This updates the live skill-folder layout described in [0064](0064-every-builder-works-in-a-worktree.md); builder isolation stays the same. Installation starts only the hub server: the hub session remains the optional dev-time role in [0068](0068-the-hub-session-is-a-dev-time-role.md).

On the existing Mac, the real `~/.claude/skills/join-web-ts` checkout moves to `~/dev/kickflip` once no builder runs, is linked back, and install runs from the new location to check the links and restart the hub. This is a one-off move, outside the install command; install never moves a real folder for the owner.
