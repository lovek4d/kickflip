# Kickflip runs from a clone linked into Claude Code's skills

Kickflip is cloned into any folder, for example `~/dev/kickflip`, and that clone is the code that runs. The owner chose this layout in `install-layout`: `web-ts install` links `~/.claude/skills/join-web-ts` to the running clone and `~/.claude/skills/web-ts-hooks` to its `hooks-plugin/`, then installs the hub's login item and Tailscale mapping. This gives a new Mac an install path and keeps the Git checkout independent of Claude Code's skill discovery. No copy of the code is installed elsewhere.

Install checks both destinations before creating either link. An existing real directory is kept only when its realpath is the intended target itself; any other real directory or file is refused. Correct links are kept, including relative links. Wrong or dangling links are refused with a message telling the owner to remove that link explicitly before retrying, even with `--force`. Refusing rather than automatically retargeting a link avoids silently switching a running installation to another checkout. The link function accepts the home directory, skills directory and clone root, and can run alone without launchd or Tailscale.

Board repos belong in `<clone>/.repos/<owner>/<repo>`, with `reposDir()` in `shared/repos.mjs` owning `<clone>/.repos` for the repo picker. That directory is gitignored. Land's test discovery skips `.repos/` and `node_modules/` at every depth, so a board's checked-out project cannot become part of kickflip's suite. The repo picker clones through a temporary directory inside `.repos` and reuses one clone per repo, guarded by a renewable lock ([0073](0073-a-new-board-chooses-a-repo-and-branch.md)); installing kickflip creates no board repos.

Live state stays in `~/.claude/web-ts/`, including the manifest, sites, settings and builder worktrees. Relative code paths resolve from the running modules, and builder and land defaults use the running clone rather than a hardcoded skill location. Node resolves symlinked main modules to their real paths, so commands work both from the clone and through the installed link. The hub's login item is the exception: its program path goes through the `join-web-ts` link, which install has just checked points at this clone, so launchd's KeepAlive and login restarts keep working when the clone moves and the link is pointed at its new folder, without rewriting the plist. This updates the live skill-folder layout described in [0064](0064-every-builder-works-in-a-worktree.md); builder isolation stays the same. Installation starts only the hub server: the hub session remains the optional dev-time role in [0068](0068-the-hub-session-is-a-dev-time-role.md).

On the existing Mac, the real `~/.claude/skills/join-web-ts` checkout moves to `~/dev/kickflip` once no builder runs, is linked back, and install runs from the new location to check the links and restart the hub. This is a one-off move, outside the install command; install never moves a real folder for the owner.
