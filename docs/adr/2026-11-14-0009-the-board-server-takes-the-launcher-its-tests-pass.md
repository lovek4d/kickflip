# The board server takes the launcher its tests pass

`startServer` takes `launch`, which starts each agent the board launches: a builder, lander, rebase run, planner, visual agent or helper. It takes `agents.mjs launchAgent`'s arguments (`{kind, model, cwd, site, prompt, log, resume}`) and answers as it does (`{pid, sessionId, log}`, or a rejection when the agent can't start), and is `launchAgent` itself unless a test passes its own. `headless.mjs` `launchBuilder`, `resumeBuilder` and `landByBuilder` take it as an option and pass it down, so every launch the server makes, a resume included, goes through the one function.

board/headless.test.mjs runs the server in its own process ([the board server starts in process](2026-11-13-2210-the-board-server-starts-in-process-and-tests-await-settled.md)) with a launcher that records each launch's arguments, so a test asserts on the prompt, cwd, model and resumed session instead of on the argv a fake `claude` script logged to a file. That drops the fake scripts, `KICKFLIP_CLAUDE` and the polls on their log, and the time each fake lived, which changed what the server saw partway through a slow test (docs/test-determinism-audit.md, F1c).

The launcher's agent is still a process: a node that idles until the test ends it or ends. The server's liveness reads stay as they are (`pidAlive` for landers and tracked builders, `ps` start times for planners and stops), so a test makes an agent's process go by ending it and awaiting its exit, then tells the server about the write that follows, rather than waiting for a fake to exit on its own. Injecting the liveness reads too is left for when a test needs a process the machine can't give it.
