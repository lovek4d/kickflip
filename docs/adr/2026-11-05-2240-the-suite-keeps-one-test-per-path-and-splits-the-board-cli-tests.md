# The suite keeps one test per path and splits the board CLI tests

The owner, 11/05: "need to audit CI tests, see what we actually benefit from and trim out redundant or unnecessarily long running ones". The audit (#291) measured board/board.test.mjs as the suite's critical path: 149 s of a 190 s run, about 510 calls that each start node for board.mjs, run one after another in one file. Its answers: split that file by command (gh291-board-test-split), make ps's timeout something a test can shorten (gh291-ps-timeout), apply every duplicate group (gh291-duplicates) and drop the tests of removed features and constants (gh291-stale-tests).

- **board.test.mjs is six files by command.** `board-threads` (reply, thread, push, install), `board-questions` (questions and prototypes), `board-items` (item, ask, lineup, holds and blocking), `board-builder` (builder start, progress, calls, dispatch, the SubagentStop hook), `board-land` (land, builder done, finish, merge) and `board-settings` (settings, rules, reviewers, review, tickets, GitHub). Every test still runs the real CLI. They share `board/board-fixture.mjs`: the per-test scratch HOME, its two boards, and the helpers. `home` is a live binding the fixture's `beforeEach` reassigns. node --test runs the files side by side, so the slowest one now sets the length.
- **A stalled ps is waited out fast.** `ps()` in hub/live.mjs times out at `KICKFLIP_PS_TIMEOUT_MS` when set, else 3 s. A test of a stalled ps sets 200 ms while the stall lasts. The stand-in ps (`stallingPs` in shared/test-helpers.mjs) counts the calls it hung, so the watcher test waits for two checks to stall instead of sleeping 15 s. The stale-board test's fixed 3 s sleeps became conditions too: the new server code waits on a release file instead of a timer, and the test waits until the hub proxies to the restarted server.
- **One test per path.** A rule keeps its cheapest test, plus one test of the wiring where a server or the CLI feeds it. The cross-site header matrix runs only in hub/cross-site.test.mjs; the three servers check each guard once. Try and main badges, and when an idle stretch pushes, are domain.test.mjs's; the server tests check only that the server feeds them. Routes named after object properties run end to end on one route each; the in-process lookup test covers each name. Contained tests were cut or folded into the test that contains them: Next on a build start, the phase bars, boolean settings, try shutdown, the dry run, the prototype url refusals and the held card's action row.
- **No test of a removed feature or of a constant.** These were dropped: the install_script setting, the followup and status commands, and assertions that a constant equals its own value.

The one test kept against the audit: view.test.mjs's check that Waiting on you names a card's topic from its card. It is the only check that the questions view passes the board's items to `cardTopics`.

Considered:
- running main() in-process instead of a node per call (gh291-board-test-split): it would lose the check that each CLI call really runs, and it means rewriting about 510 calls;
- leaving the ps timeout to #289 (gh291-ps-timeout): #289 added the stand-in ps but kept the fixed timeout and the 15 s sleep;
- keeping guards that a removed command stays gone (gh291-stale-tests): a guard like that catches nothing a change could break.
