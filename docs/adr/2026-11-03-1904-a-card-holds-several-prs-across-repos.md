# A card holds several PRs across repos, each with its own badge and polling

The owner, on kickflip.sh #5, which had two draft PRs, lovek4d/kickflip.sh#6 in the board's repo and lovek4d/lovek4d.github.io#1 in another: "where there are multiple draft PRs or multiple PRs in general, I would like for there to be multiple badges as well." A card stored one `pr` number in the board's repo, so only #6 got a badge, polling and merge tracking; the other PR showed only as a thread link.

- **The wave entry stores a list.** `prs: [{repo?, number}]`, in the order they were added; an entry without `repo` is in the board's repo (the board's `github`, else the wave's `repo`). An older entry's `pr: <n>` reads as one PR in the board's repo, and the next `--pr` moves it into the list. Every reader goes through `shared/card-prs.mjs` `cardPRs`.
- **`item set --pr` adds.** `--pr owner/repo#n` or a bare number, repeatable in one call; a PR the card already holds stays as it is, and nothing replaces one.
- **Each PR is polled like the board's own.** The hub's poll (`hub/boards.mjs` `prsOf`) and the board server read every PR on an unfinished card in its own repo; `board.mjs pr` prints a line per PR naming its repo, and `pr comment`/`pr reply` take `owner/repo#n` for one in another repo.
- **The least-ready PR decides the card.** `leastReady` ranks not read yet, draft, failing CI, waiting on review, approved, then merged or closed; the card's lane, what it waits on and its Next follow that PR as they followed the one PR before, and `it.pr` on the board is that PR's view, beside `it.prs`, all of them.
- **Each PR has its own badge.** `prChips` shows one per PR, in the card's order, with that PR's `PR_STATE` ([a merged card reopens on a message, and its PR badge shows the PR's state](2026-11-03-1843-a-merged-card-reopens-and-its-pr-badge-shows-the-prs-state.md)), CI and link.
- **Merge waits for every PR, and merges them all.** The owner's Merge shows only when every open PR is approved, green and CLEAN; `board.mjs merge` checks each, naming the PR before each reason on a card with several, then squash-merges the open ones in the card's order, leaving a merged or closed one be. A failure stops it, naming the ones it merged first.
- **Done once every PR has landed.** The card closes as merged once every PR has merged or closed with at least one merged (`allLanded`), its line naming the merged ones ("Merged PRs #6, lovek4d/lovek4d.github.io#1."); all closed with none merged reads closed, as one closed PR did. The hub's Linear moves and the Slack review links read the card the same way.

Considered: replacing the card's PR on each `--pr` (a second repo's PR would drop the first), and the card done once any PR merged (the other repo's change would be left unmerged with the card in Done).
