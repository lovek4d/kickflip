# A New board can anchor on a folder on this Mac

The three source tabs below became one field shared with New course ([New board and New course share one source field](2026-11-21-2300-new-board-and-new-course-share-one-source-field.md)); what a folder means for a board is unchanged.

The owner asked (T-518, 11/16): "Can a new board anchor on an existing directory? Could even offer to make it a git repo if it is not already." Until now New board took only a GitHub repo or another host's git link and cloned it under the clone home, so a folder already on the Mac could be a board's repo only through `kickflip join` in a terminal, or by pushing it somewhere first. The owner picked prototype take C (two steps, a folder then the details), a "Make it a git repo" toggle that applies on Start, and, for a folder that is a clone of a GitHub repo, a GitHub board working in that folder.

- **Three sources.** New's Board step 1 opens on GitHub · Other git host · Folder on this Mac. GitHub is today's search-or-paste list; Other git host is the paste-a-link field alone. Change repo has no sources: it still clones.
- **The folder.** A path field, `~/` or absolute, lists the folders under what is typed as you type (`GET /_hub/folders?q=`, `hub/folders.mjs folderSuggestions`: hidden ones only once the name starts with a dot, never `~/.claude` or a symlink). A path not ending in a slash is looked up (`GET /_hub/folder?path=`, `folderInfo`) and shown as one dot line: green "Git repo · github.com/owner/name · trunk" (or the other host's link), blue "Git repo · no remote · lands won't push", orange "Not a git repo", red the refusal. Next opens step 2.
- **Safety.** The folder must be a real directory inside home, not home itself, not in `~/.claude` (the clone home and worktrees live there), reached through no symlink, the root of its repo when it is in one, a repo with at least one commit, and not the repo of a board that is open, starting or closed. The hub never deletes it; closing the board leaves it, as it leaves any board's repo.
- **Make it a git repo.** For a folder that isn't a repo, step 1 shows the toggle ("git init, and commit what's there as the first commit. Applies when you tap Start.") and Next waits for it. On Start the hub, once the route is known to be free, runs `git init -b main`, `git add --all` (so a `.gitignore` there is honoured; the hub adds none) and commits "Initial commit", empty if the folder is. A failed commit (no git identity, say) removes the `.git` it made and refuses with git's line, so the folder is as it was.
- **Step 2.** The folder's line, its branch read from the folder (its default first; fixed to main for a folder git init will make a repo), Name (the folder's name), Description and Tickets. GitHub issues need the folder's origin to be on GitHub. Its note says what lands do: "lands fast-forward trunk and never push" with no remote, "lands fast-forward trunk in this folder" with one.
- **The start.** `POST /_hub/new-board {name, folder, git_init?, branch?, purpose, tickets}` records a Starting record with `folder: true`, `repo` the folder, and `github` or `remote` from its origin. There is no clone step: the record starts at "starting". The session starts in the folder, which the hub first marks trusted for Claude Code (`startSession` `trust`), the owner's pick in New being the consent, as the New board tap is for a clone ([the hub trusts the clones it makes](2026-11-02-1549-the-hub-trusts-the-clones-it-makes.md)). Retry keeps the folder.
- **A local board.** The join records the board `local: true` with the folder's branch, and its GitHub repo or remote when it has one: a Local board, as `kickflip join` makes. Its builders branch from the folder's own branch and land by fast-forwarding it, and its Main pulls from origin fast-forward only ([a local board builds and lands on its default branch](2026-11-03-1851-a-local-board-builds-and-lands-on-its-default-branch.md), [a local board's Main pulls from origin on its own](2026-11-03-1914-a-local-boards-main-pulls-from-origin-on-its-own.md)). A board on a clone is reset to origin on every poll, which in the owner's own folder would throw away their work, so a folder is never that. Lands already refuse while the folder has uncommitted changes, so nothing there is lost.
- **Settings.** A board with neither a GitHub repo nor a remote reads "Local only, lands don't push" on its repo row, beside its branch.

Considered:
- a GitHub clone folder as a board on the shared-clone path, opening PRs: that path fetches and resets its checkout to origin, which a folder the owner works in can't take. A Local board on GitHub keeps GitHub issues and links, and lands by merging into its folder's branch with no Landing choice, as any Local board but the hub board does;
- "Make it a git repo" as a button that runs git init at once (the owner chose the toggle);
- the folder source in Change repo, which would move a running board off its clone onto a folder; not asked for.
