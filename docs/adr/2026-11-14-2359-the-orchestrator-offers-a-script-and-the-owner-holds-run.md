# The orchestrator offers a script in a thread, and the owner holds Run

Permission rules often stop the orchestrator from doing something the owner plainly wants: a `kill`, moving a pushed tag, `tailscale serve`, an amend on a builder's branch. Until now it handed over a command for the owner to paste into a terminal, often over SSH from a phone. The owner (T-223) asked for the board to run it instead, once they had read it and tapped. Prototype round 1 settled the shape: a message with a script card (take A), and while it waits, Action needed with a push.

- **The offer.** `board.mjs thread <key> --script <file> --text "<what it does and why I couldn't>"` posts the orchestrator's message with `script: {id, body, sha, host, user}` on its line. `body` is the whole script (64 KB at most, never cut short on the page), `sha` its sha256, and `host` and `user` where the board server runs it (`os.hostname()` without `.local`, and `os.userInfo()`). It goes on a task only, not an ask's thread. Its line can't be edited; a newer offer on the same task replaces a waiting one, which then reads replaced and can't run.
- **Its state is derived, never stored.** `script-run {key, id, sha}` (the owner's Run), `script-result {key, id, exit, output, timedOut, ms, log}` and `script-decline {key, id}` are events in `data/events.jsonl`. domain.mjs `scriptStateOf` reads them: finished (exit 0) or failed once the result is in, declined, running from the Run, waiting while it is the task's newest offer, else replaced. `threadOf` puts the state on the offer's message.
- **Action needed and a push.** A task with a waiting offer has action kind `script`, "Run or decline the script", right after stalled. It reads Action needed in orange, as every Action needed does (CONTEXT.md Colour rule), and not the red the notes said: red is for faults. It pushes at once like every other Action needed (`ownerActions`), and it is a tap row on the ? page with the word Run, which opens the task. T-375 unifies those rows.
- **Run is the owner's and is held.** The board server takes `script-run` and `script-decline` only from the owner: neither is in the kinds a Full shared person may send, so the server answers a shared person 403 and the page hides the buttons under `.shared-view`. Run has to be held for 900 ms while its bar fills. Letting go sooner sends nothing, and from the keyboard it asks a confirm instead. Decline asks a confirm. Neither tap goes through the thread's outbox, so a reload never sends one again.
- **A stale page can't run changed text.** A Run names the offer's id and the sha of the text the page drew. The server refuses it with 409 when the sha differs, and with 400 when the offer isn't waiting (already run, declined or replaced). An in-memory set stops two taps at once from both getting through.
- **The run.** The server records `script-run`, then starts `board/bin/script-run.mjs` detached, so a restart of the server doesn't stop the script. The runner runs the script with `/bin/sh -c` in the board's repo folder (worktree.mjs `builderRepo`). A board with no folder recorded refuses the Run before recording it. A run gets 10 minutes, then its process group is killed. stdout and stderr go together into `~/.claude/kickflip/logs/script-<id>.log` as they come, and the last 64 KB are kept for the result. The runner posts `script-result` through the board server (hub/boards.mjs `appendEvent`), so it wakes the watcher.
- **What the orchestrator hears.** `script-result` wakes it with the exit code, the last 500 characters of the output on one line, and the log's name. `script-decline` wakes it so it doesn't try the same thing another way. `script-run` wakes it too, with a line saying the result follows and there is nothing to do yet. Making the tap record-only was the first plan, but this build couldn't edit the record-only list (see the build's judgment calls).
- **The card.** Under the message come "⚠ Runs on <host> as <user>" in orange, the script's line count and the whole script in monospace, then by state: Hold to run and Decline; running with a Live output link to the log page; finished with its output folded; failed in red with the last 20 lines of output and the exit code, and "stopped at its time limit" when it timed out; declined; or replaced. A finished or failed run links its full output.
- **Left out.** There is no Stop while a script runs (the prototype drew one; the notes don't ask for it). Nothing marks a run whose runner died, say at a reboot, so its offer stays running.
