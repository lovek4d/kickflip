# The hub starts in process for its tests

Card #656, F2 of docs/test-determinism-audit.md. Every hub test spawned `hub/hub.mjs` on a port from `freePorts`, waited for its `hub on` line, then polled for what its 2 s reconcile, 15 s tick and 2 s share check did on their own time. The tick read the real load, so a busy Mac held work (try.test's 409), and the first poll fired 60 s after start, racing a test's own poll. Under the owner's rule (docs/adr/2026-11-13-2130-the-main-suite-holds-no-new-timer-waits.md) a test waits on state, not on time.

- **`startHub()`.** hub.mjs exports `startHub({port, now, codeRestarts, log, probe, readMachine, gate, awake, ticks})` and resolves once the hub listens, with `{port, reconcile(), tick(), poll(), endUnshared(), settled(), close()}`. Running `node hub/hub.mjs` calls it on `KICKFLIP_HUB_PORT` (else 4500) and closes it on SIGTERM or SIGINT, as before. Each call's state (sites, polls, prompts waiting) is its own, so a test can close a hub and start another on the same files as a restart.
- **`ticks: false`.** The hub runs no timer of its own: the test runs each reconcile, tick and poll, and the tick starts no poll. So the 60 s first poll can't race the test's, and a site's down or up follows the probes the test runs.
- **`settled()`.** Resolves once every pass started so far, by a call, a timer or a request, is done: reconcile, tick, poll, wake, session check, router drain and the Restart hub run after its answer. Reconcile runs one pass at a time; a call while one runs waits for it, then runs its own, so the pass a test awaits reads the files as the test left them.
- **Injected host.** `readMachine` stands in for the Mac's load and memory pressure (shared/machine-gate.mjs), `probe` for a site port's TCP check, `gate` for the owner gate (an `ownerGate({now})` whose retry the test moves past), `awake` for the Keep awake controller (`caffeinate({spawn})`), and `now` for the supervisor's restart backoff, the poll schedule and the caches. `serverAnswers`' 30 s wait for a restarted board stays on the wall clock: with a frozen `now` it would never give up.
- **Sites get the hub's port.** A site the hub starts gets `KICKFLIP_HUB_PORT` set to the port it listens on, which a port of 0 needs, and which a hub on its default port already meant.
- **One HOME per test file.** push, prompts, boards, live, router and sessions read `os.homedir()` as they load. So `startHub()` takes no home: hub/hub-fixture.mjs sets HOME, a PATH of failing stand-ins for gh, tailscale, launchctl, claude, tmux and the rest, and a Restart hub command of `/usr/bin/true` as it loads, and a test file imports it first. Its tests share that home and reset what they need. Making those modules read the home on each call would let tests in one file differ, but it touches every hub module and isn't needed for any test here.
- **What stays a process.** A board server the hub must start is still a child, since starting and restarting it is what the test checks; it tells the test it listens (S5, the fixture's `serverSignals()` preload) instead of being polled. Its port still comes from `freePorts`, since the manifest names it before the server starts.
- **Restart board reconciles itself.** Its wait for the restarted server runs a reconcile pass before each check, so the server is stopped, started and probed by the restart, not by the next 2 s pass; a hub with `ticks: false` would otherwise never restart it.
