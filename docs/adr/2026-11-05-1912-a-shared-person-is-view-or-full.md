# A shared person is View or Full

Superseded by [the hub has no sharing](2026-11-18-0700-the-hub-has-no-sharing-only-the-owners-tailnet-identity-gets-in.md): there is no sharing; any login but the owner's is refused.

#242 shared a board view only (docs/adr/2026-11-05-2215-a-board-is-shared-view-only-with-a-tailscale-login.md). The owner asked for fuller permissions as a later card (#295, share-permissions-notes.md), answered the grill, and picked take C of prototype round 1: per person, View or Full.

- **Two levels, set per person (gh295-proto-levels: C).** board.json `share` keeps a bare login for View, so #242's lists need no migration, and stores a Full person as `{login, level: 'full'}`. Board settings' Sharing gives each person's row a View / Full control under their login, with what that level can do, and saves a tap at once through `POST /api/share {login, level}` (store.mjs saveBoardShare). Only someone listed can be given a level; Add still adds as View.
- **Full is answering and acting (gh295-answer: A, gh295-act: A).** A Full person answers questions, writes thread messages, attaches files, taps card buttons and adds New tasks. Merge and Board settings stay the owner's at every level, as do a PR review's Post and the header's GitHub check.
- **The hub passes two paths; the board checks the kind.** The hub sees only a path, so `hub/share.mjs shareReach` passes a Full person's POST to their board's `/_claude/events` and `/api/upload`, and gives every other write `view-only` as before. The hub forwards it with `X-Kickflip-Shared: <login>`, and deletes that header from every request of the owner's. The board server (sharedWriter) takes a request carrying it only if board.json, read again, lists that login as Full, only for those two paths, and for events only for a kind on Full's list (`FULL_KINDS`); anything else is 403 `{error}`. A hub-set header, rather than the board matching Tailscale-User-Login against its share, keeps the owner the owner even if their own login is ever listed.
- **Named in the thread; Claude acts as on the owner's (gh295-who: A).** The board records a Full person's event with `data.shared_by: {login, name}`, the name from Tailscale-User-Name, and strips any `shared_by` the page sends (`by` is lineup-move's direction); each answer of a Send carries it too. Thread lines stay `who: 'love'`, so everything that reads the owner's lines reads theirs the same, and carry `by` (their name, else login), which the thread shows instead of "You". The lines the server writes for their tap, Held, Resumed, Marked done and Stopped its builder, carry it as well. The session acts on their events as on the owner's.
- **No pushes; the shell shows their board's questions (gh295-notify: A).** Pushes and `/_hub/presence` stay the owner's, as in #242. A Full person reaches the board's Questions page and answers there, and the sidebar still carries no waiting counts, which are the owner's.
- **The shell follows the level.** `sharedSidebar` sends `shared: {by, full: [route]}`. shell.js marks the page `.shared-full` on a board in `full`, which shows the +, the composers and a card's buttons again; Board settings and the architecture review stay hidden at every level, and Merge shows disabled, as take C drew it. A Full board's strip reads "Full. Shared with you by <owner>. You can answer and act. Merge and Board settings are <owner>'s." A level change ends that person's open `/_hub/stream`, as removing a share does; its EventSource comes back with the new level, and the shell redraws the class and the strip.
- **Outside the two paths.** Read marks, hiding an event for every device, Visit link builds (`/api/try`) and the board's own stream stay the owner's at every level.
