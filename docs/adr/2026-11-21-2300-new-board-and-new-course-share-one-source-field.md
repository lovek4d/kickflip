# New board and New course share one source field

The owner asked (T-717, 11/18): "Course should actually allow selecting a git repo. Also would like to review the new flow in general to polish it up a bit visually." They picked an optional "Learn from a repo" row for Course, then, on the polished flow, wrote "im imagining a common picker for git repo/other repo/device folder that both board and course use somehow", and chose take A of the source picker: one field for any source. This replaces the three tabs ("GitHub · Other git host · Folder on this Mac") of [a New board can anchor on a folder on this Mac](2026-11-18-0724-a-new-board-can-anchor-on-a-folder-on-this-mac.md); what a folder means for a board is unchanged.

- **One field.** `board/public/dialogs.js sourceField` is Board's step 1 ("Source"), Course's optional "Learn from…" and Change repo's "Repo". It reads the kind from what is typed: a path (`~/`, `/`) is a folder, a link on another host is a git remote, a GitHub link or `owner/name` is a GitHub repo (one in the owner's list is picked with no lookup), and other text filters the suggestions. Empty, it suggests by kind: Your repos, Other remotes and Folders on this Mac. Tapping a suggestion fills the field, as typing it would.
- **Recent sources.** Other remotes and Folders on this Mac are the ones the hub's boards (open, starting, then closed) and starting courses use, each once, with who uses it (`hub/folders.mjs recentSources`, sent as `recent` on `GET /_hub/repos`). Board leaves out a folder that is already a board's repo, since it can't anchor there; Course keeps it, since it only reads it. A typed path still lists the folders under it.
- **The line.** Under the field one line says what was found and what happens next: green with the name, its kind ("GitHub repo", "Git remote", "Folder"), access and clone state, and what Board or Course does with it ("Board clones … into the shared clone home", "Board joins ~/dev/x in place: no clone, nothing copied", "/teach reads …; lessons stay in the course's pages folder"). A source that can't be used turns the field red with the reason. A board's folder that isn't a repo keeps the orange "Not a git repo" line and Make it a git repo.
- **Next and Start say why.** Board's step 1 now ends in Next for every kind (it was a tap on a repo row, or Next for a folder). A disabled Next or Start shows its reason above the buttons: "Choose a repo, a remote or a folder to continue.", "Fix the source to continue.", "Name the course to start.", "Fix the source, or clear it, to start.", and so on.
- **A course's source.** `POST /_hub/new-course {name, learn, github | remote | folder?}`. A repo is cloned into the shared clone home on its default branch first (the Starting record reads cloning, with the clone's percent, as a New board's does; `new-board.mjs cloneFor`), a folder is read in place (`readableFolder`: folderPath's checks, but a board's repo, a folder inside a repo or a plain folder is fine, as a course only reads it; `GET /_hub/folder?path=…&read=1`). The session still runs in the course's own folder under pages, so the source stays clean; it gets the clone or folder through `--add-dir` (`startSession` `dirs`, placed before the other flags since `--add-dir` takes values until the next one), and its /teach prompt says to read it and never write to it. The source is kept on the Starting record as `source`.
- **Polish.** The phone New sheet is full height with its footer pinned at the bottom, Start full width with Cancel under it; one spacing rhythm across both forms; the Course textarea has the inputs' look; Board's steps read "Step 1 of 2 · Choose a source" and "Step 2 of 2 · Board details" with Back as a link; Course's name reads "Name" with "Opens at /route/" under it.

Considered:
- Topic | Repo inside Course, with the codebase as the subject, and running the session inside the repo's clone with lessons committed on a branch (the owner picked the optional row);
- Repo | Remote | Folder tabs, or a "Choose source…" button opening a stacked picker (the owner picked one field);
- recent folders from a separate history file: the manifest already records every board's and starting course's source, and a file would be one more thing to keep in step.

Left as it was: the Starting row's icons and words, the failed-start sheet and the down-course confirm.
