# A Haiku router files each incoming request on a board

A request that arrives at the hub without naming a board (for now only a Slack @kickflip, T-228) needs a board. The owner asked for "an uber orchestrator (even haiku) that just classifies incoming requests to a given board" (T-230), and settled its shape in a grill and two prototype rounds.

- **It only routes.** `hub/router.mjs` `routeRequest({text, files, from: {via, by, link}})` picks a board and files the request there as an ask; that board's orchestrator sorts, discusses and builds it as any other ask. Every board's own New task box, GitHub and Linear issues and reviewers' Slack requests already know their board and don't go through it.
- **One Haiku call per request.** `claude -p --model haiku --output-format json --tools "" --json-schema … --no-session-persistence`, whatever the hub's Claude model or Codex share, since it never builds. Its prompt holds each board's route, title, manifest `description` and its 15 most recently changed open card titles, and it answers `{route, reason}`. With one board there is no call.
- **Best guess, no fallback, no learning.** It always files on the board it picks, never on the hub board when unsure: most users have no hub board ("Hub orchestrator is not something to rely on"). A later `ask move` corrects it and teaches it nothing.
- **Held while paused.** Every request waits in `~/.claude/kickflip/route-queue.json` until filed. While usage is paused it stays there, and the hub's 15-second tick routes it once the pause lifts. A failed call stays queued with its error for the next tick; after three tries the request goes to the first board in the manifest, its reason saying the router failed. A filing the board may already hold leaves the queue rather than risk a second ask.
- **The thread's status line.** The ask carries `routed {reason, via, by, link, at}`. The board draws it (domain.mjs `threadOf`, never written to the thread file) as the status line "Routed here from Slack: <reason>", linked to the message, just above the ask, in the same blue as Created: it is info the owner reads and may act on with `ask move`.
- **The hub page's Routed section.** Under Boards, newest first, from `~/.claude/kickflip/routed.json` (the last 30) and the queue. Per the owner ("reuse exactly the component for the board new section, make it look the same"), it is the board's New strip, `BoardUI.newStrip` with a `Routed` head, and each row is a New entry: the message, a blue link "Routed to /board T-n · title" to the card it became ("Added to" once folded, "Moved to /other T-m" after an `ask move`), then a muted second line with sender, source, time and the reason. A queued request reads the strip's grey waiting…. Empty, it says so.
- **No Dismiss on the hub.** A board's New entry dismisses through its card's read mark, which the hub has none of; the section is a recent log, not a to-do, so it has no Dismiss.
