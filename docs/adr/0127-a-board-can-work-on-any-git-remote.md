# A board can work on any git remote

The owner asked on hub/INT-188 for a pasted git link to make a board, even for a repo gh can't see, and settled the shape on hub/INT-189: plain git only, a finished card pushes its branch and is Done once that branch is merged, and the open card says where it went (take A of `remote-card`). This amends [0078](0078-a-pasted-github-link-picks-any-reachable-repo.md), which refused other hosts, and [0113](0113-the-hub-trusts-the-clones-it-makes.md)'s clone shape.

- **Identity.** A board on another host stores `remote: <link>` in the manifest and no `github`. A GitHub link still makes a `github` board. The link is `https://host/path`, `ssh://[user@]host[:port]/path` or `user@host:path`, nested groups allowed; a password or token in it, a query, a local path, `file://`, a github.com host and a host without a dot are refused (`remoteFromInput` in `hub/repos.mjs`). A host without a dot is refused so that a clone folder never looks like a GitHub owner's.
- **Clone.** The clone is `.repos/<host>/<path…>`, lowercased, with the same symlink and stay-inside checks. `isClone` accepts that shape when no clone sits above it, so the trust mark still covers only the hub's own clones.
- **Credential.** Lookup, branches, clone, fetch and the poll's fetch use git's own credential (SSH agent, keychain helper) with every prompt off: `GIT_TERMINAL_PROMPT=0` and, unless `GIT_SSH_COMMAND` is already set, `ssh -o BatchMode=yes` (`remoteGitEnv`). Kickflip holds no token for another host. A failure shows git's line and the hint "check git can reach <host>: git ls-remote <link>" (`gitReachFault`).
- **Picker.** The search box takes the link, or a host without gh signed in shows a paste field under its sign-in note. `GET /_hub/repo?remote=` checks it with `git ls-remote --symref`; its row reads host/path with the host where a GitHub row says Private or Public, Last push unknown, and the clone path. Branches come from the same ls-remote.
- **Builders** branch from `origin/<board branch>`, as on a GitHub board.
- **Finish.** A card's work leaves the board as a pushed branch: the session pushes it, then runs `board.mjs item set <card> --pushed <branch>`, which records `pushed {branch, at}`, clears building and fixing, closes the builder, and moves its ticket to In Review. The card waits In Review on the owner, its next step "merge <branch> into <board branch>", with no action and no push.
- **Done.** After the hub's poll fetches the board's branch, it lists the remote's branches once and moves each pushed card to Done (`settlePushed` in `hub/try.mjs`): as merged once the branch's tip is in the board's branch, and once the branch is gone from the remote, as merged when its last known tip is in the board's branch and done otherwise, since a squash merge leaves no trace. A thread line says which.
- **The card.** The open card's Links row reads "Pushed INT-12 to gitlab.com · 25m ago" where a GitHub card has Review on GitHub. Tapping it copies the branch name and reads "Copied the branch name" for a moment. There is no link to the host and no Copy button. The In Review header names the repo, host/path, in place of the GitHub line and its refresh, and its mark still opens Hub links.
- **No PR features.** PR polling, auto-merge, reviewer links, Linear moves from PR state and the GitHub polling link stay keyed on `github`, so a remote board has none of them, and its setup checklist has no GitHub step. GitHub issues needs a GitHub repo: Board Settings and New board grey it out with the reason, the way Linear waits on Hub's key ([0117](0117-a-board-picks-linear-only-while-hubs-key-works.md)), and `settings set tickets`, New board and Change repo refuse it.

Considered: GitLab merge requests through `glab` (the owner chose plain git only); an "Open merge request" link built from a per-host URL pattern (take B of `remote-card`); and nothing about the push, with Mark as done for a merge the hub hasn't seen (take C).
