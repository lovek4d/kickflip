# A merged card reopens on a message, and its PR badge shows the PR's state

The owner, on #142, after writing three messages on kickflip.sh #3 once its PR merged and seeing it stay in Done: "conversations restarting in a done item were supposed to move them into in progress until the conversation closes again." On the look: "make the done also have that same style of it turns merged purple … a better standard expression everywhere than having a merged tag. And maybe gives us an opportunity to make that an enum as well. So the PR badge has a state, and maybe that can link to the PR directly." This supersedes [a message or question on a Done card reopens it until the owner's Done](2026-11-02-1952-a-message-or-question-on-a-done-card-reopens-it.md)'s merged exception.

- **A merged card reopens like a done card.** An owner `item-message`, or a question on its topic, newer than the card's close reopens a card with status done or merged, or whose PR merged (`board/domain.mjs` `workItem`). The close is the newest of the owner's Done, the card's status change, `merged_at` and the PR's `mergedAt`, so a message from before the merge doesn't reopen it. The reopened card leaves Done whatever its PR's state, then follows [a message or question on a Done card reopens it until the owner's Done](2026-11-02-1952-a-message-or-question-on-a-done-card-reopens-it.md): In Progress until Claude answers, then In Review waiting on the owner's Done. A dropped card, or one whose PR closed unmerged with no done status, stays closed.
- **The owner's Done closes it again, and the wave file stays merged.** The board reads the `card-done` tap as newer than the status and closes the card; it keeps status merged, and `recordOwnerTap` leaves a merged item's wave file as it is. The PR stays merged.
- **`question add` takes a merged card's topic.** It no longer refuses one; the question reopens the card like any question on a done card.
- **One PR state, on the PR badge.** `PR_STATE` in `board/public/ui-enums.js` is open, draft, merged or closed. `workItem` sets it as `pr.status`: merged once GitHub says so or the card's status or `merged_at` does, else GitHub's closed, draft or open, and null before GitHub is read. The PR badge (`ui-cards.js` `prChips`) is the only place it shows, on every card in every lane, linking to the PR: green check for open, orange dot for draft, purple check for merged (the `merged` badge tone, `--color-merged` over `--purple` in `shared/colors.css`), red cross for closed, its title the state. The separate merged and closed chips are gone. The state is per PR, so a card with several PRs (#143) gives each its own.

Considered: keeping a merged chip beside the badge, or a merged footer item (takes A and B of the prototype); the owner picked C, the badge itself turning purple.

Superseded in part by [a card stores its lane, and facts replace statuses](2026-11-07-1400-a-card-stores-its-lane-and-facts-replace-statuses.md): a merge is merged_at on the PR's entry and a move to Done; the card's reopen is stored with reopened_at.
