# An idle board pushes once when it has gone idle

The owner asked on #164 for a push "when things are fully idle again". The grill first settled on a reminder a session arms with a trigger the board server fires (`board.mjs remind --when idle`), shown on the board and then in Board settings. On the third prototype round the owner dropped the reminder: "instead we have a setting that is a idle notification and it's just a checkbox and it sends you a push notification saying that the board has gone idle and maybe a summary of the recently closed tasks or waves and it just sends you a notification if the board has been idle for let's say 15 minutes". No armed reminder had landed, so none was removed.

- **One checkbox per board.** `idle_notification` in `board.json`, off when absent (`store.mjs settingsOf`). Board settings shows it as "Idle notification", last in its Auto section, saving with no confirmation like the other Auto toggles; `board.mjs settings set idle-notification on|off` sets it too. The board server alone acts on it, so a change wakes no session: the `settings` event leaves it out.
- **Strict idle.** `domain.mjs strictlyIdle`: no agent running on an open card (nothing building, grilling or prototyping), no grill or prototype request under way, no card waiting in Orchestrator review to land, no pulled card waiting to start, and no event a session is working on (no session turn running). A Ready card nobody pulled doesn't keep the board busy: with Auto implement off it waits on the owner, and on, it is pulled at once and then counts.
- **Once per idle stretch, 15 minutes in.** The board server steps `data/idle.json {last, since, pushed}` on every board change and each minute (`server.mjs checkIdle`, `domain.mjs idleStep`). Busy ends the stretch; a stretch that reaches 15 minutes pushes once, and the next push waits until the board has been busy and idle again. The file survives a restart, so a restart mid-stretch keeps its start. Off, the file goes, so turning it on starts a fresh stretch.
- **What it says.** A `reminder` push, tag `idle`, titled "<board> has gone idle", that opens the board. Its body sums up what closed since the last idle push (`domain.mjs idleSummary`): the work cards that landed in Done, dropped ones left out, newest first with up to three refs, and each wave (lineup) whose last card closed since then. With nothing, "Nothing closed since the last idle notification." A push that fails still counts as the stretch's push, so a board with no device turned on isn't retried every minute.
- **A push the owner asked for.** Pushes still go out only when something waits on the owner ([a push goes out only when something waits on the owner, on the hub's schedule](2026-10-29-1639-pushes-only-when-something-waits-on-the-owner.md)); like a session's `--kind reminder`, this one goes out because the owner turned it on.

Considered:
- the armed reminder (`board.mjs remind --when idle`, `data/reminders.json`, a line in the header or a Reminder row in Board settings): the owner replaced it with the checkbox;
- pushing as soon as the board goes idle: the owner named 15 minutes, which also keeps the short gaps between one job and the next quiet;
- a Notifications heading in Board settings: Board settings keeps every automatic job in its one Auto section, and no Notifications heading;
- counting a Ready card nobody pulled as busy, as the grill's first idle answer said: with Auto implement off, such a card would keep the board from ever pushing.
