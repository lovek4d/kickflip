# A PR's state is a line in its message, not reactions

Superseded by [a PR's state is reactions again, and the signature is picked](2026-11-18-0434-a-prs-state-is-reactions-again-and-the-signature-is-picked.md), except its emoji picker.

A PR's Slack messages (each reviewer's link and the digest reply about it) showed its state as emoji reactions: `git_approved` once approved, then `git_merged` on merge or `x` on a close. A reaction is only added, so an approval that was taken back stayed, and a workspace without the custom emoji failed every reaction. The owner asked for the state in the message's text, edited in place, and for the emoji to be set in Hub settings with standard ones as the fallback. From the prototypes they picked a muted line above the sign-off ("Drop the reactions with this change") and a popover grid for the emoji.

**The state is a line in the bar, just above the sign-off** (`board/slack-store.mjs` `prLink`, `prState`): `:git_approved: Approved by Ann`, `:git_merged: Merged` or `:x: Closed`, and no line while the PR is open. There are only those three states: changes requested has none. Approved holds as the `git_approved` reaction did ([a chip per PR reviewer, and git_approved waits for GitHub's decision](2026-11-12-1400-a-chip-per-pr-reviewer-and-git-approved-waits-for-githubs-decision.md)): once GitHub's decision approves, or on that reviewer's message once they approved it themselves. It names everyone whose latest review approves, by their reviewer name or else their GitHub login, and never a bot. A Slack attachment's text can't be grey, so the line is plain text set apart by its emoji and its place above the sign-off.

**The line follows the state both ways.** `review due` owes an edit for each posted link and digest reply to a current reviewer whose recorded line (`state` in `pr-slack.json`, the line's words, `''` for none) isn't the one the PR's state asks for now. The hub sends the whole message again with `chat.update`, which signs it off with " · _updated HH:MM_" as the digest header's count edit does; an edit doesn't notify. An approval taken back returns the line to none. A PR the hub holds no GitHub state for is left as it is, so a PR dropped from the cache isn't edited back to open.

**No reaction goes on a PR's message any more.** A message posted before this change keeps the reactions it has, since the hub never removes one, and gets its line at its next state change: its reactions stand in for its recorded line, by their state's kind, so an old merged message isn't edited for a state it already shows. Bumps sent before bumps stopped keep their words and are never edited. A digest reply's age (“_(N days old)_”) is worked out again for an edit from its own time and its link's.

**One emoji per state, hub-wide, picked in Hub › Slack** (`hub/slack.mjs` `PR_EMOJI`, `prEmojis`; `board/public/slack-emoji.js`). The hub has one Slack token and so one workspace. A state's default is its custom emoji while the workspace has it (`git_approved`, `git_merged`), else its standard one (`white_check_mark`, `large_purple_circle`); closed has no custom one, so it is always `x`. A pick is kept in `slack.json`'s `pr_emoji` and wins over the default; Use default clears it. The rows show under the token while it works: each state's emoji, marked standard while it is the standard default, and a cell that opens a grid of the workspace's own emoji then a list of standard ones, searched by name. A pick sets the emoji of lines edited from then on; it doesn't edit the lines already posted.

This supersedes the reactions in [every PR message is the bar with no mention](2026-11-14-2300-every-pr-message-is-the-bar-with-no-mention.md), and the reactions' fallback to standard emoji, which had no record of its own.
