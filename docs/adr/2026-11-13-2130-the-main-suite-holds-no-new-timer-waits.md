# The main suite holds no new timer waits

Card #652. Lands of T-260, T-270, T-275 and T-186 failed on one day, mostly by hanging in board/server.test.mjs and board/headless.test.mjs, while each passed on a quiet Mac. The fixes before this one waited longer, nudged the server's watch, counted after the watch went quiet, or warned under 5× a budget. None removed the dependence on time. The owner's rule: "we should not have any timer based tests in main suite, that should be a perf bench specific action".

Supersedes docs/adr/2026-11-12-1110-a-test-waits-on-state-and-fails-only-at-5x-its-budget.md for the main suite: a test waits on a state it is told about, never on a budget, and a check of speed runs only on the perf bench.

- **The audit.** docs/test-determinism-audit.md lists each test whose result or run time depends on the machine: what it waits on, the seam that replaces the wait, and whether the module under test already takes that seam's option. It groups the seams into fix tasks (F1–F10), says where each timing check goes (bench, delete or rewrite), and lists first the tests whose result load changes today.
- **The guard.** board/timer-free.test.mjs counts each main-suite test file's timer waits: calls of `setTimeout`, `sleep`, `delay`, `until`, `untilHeard` and `boardSees`; elapsed-time reads (`Date.now()` less a variable, `performance.now`, `process.hrtime`); and time limits (`timeout:` a number, `AbortSignal.timeout`). A line that is a `//` comment doesn't count. Each file's count is listed in the guard as it stood at this commit. A file over its count fails, as does a new file with any. A file under its count also fails until its count is lowered, so the list always says what is left. A main-suite file is a tracked or untracked `*.test.mjs`; the bench's `*.bench.mjs` files are not.
- **Every run checks it.** The guard is in board/test-map.json's `core`, so a new test file is checked by the land that adds it, even though nothing it imports changed.
- **What the guard doesn't see.** A wait inside a helper counts once, where the helper is written (`putWave`'s `launchesGone`, server.test's `cardsMarkedRead`), not at each call. A time limit inside the code under test isn't counted; the audit lists those that flip a test's result (its "Code under test has its own time limits" table), and F9 takes them on.
- **No fix in this card.** The fix tasks are filed from the audit. T-290 (tests wait for free memory) still stands for the machine, but the tests must pass under any load without it.
