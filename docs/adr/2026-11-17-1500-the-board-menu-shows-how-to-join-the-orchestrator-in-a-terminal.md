# The board menu shows how to join the orchestrator in a terminal

The owner asked for a command to join a board's Claude Code session from a terminal and chat with it directly, shown even while the board's server isn't answering (T-467).

- **Attach only, the orchestrator only.** The command opens the running orchestrator session live, and leaving it leaves the session running. Builders, planners and landers get nothing: they run as one-shot `claude -p` processes that can't be attached to, and a take-over (stop, resume interactively, hand back) was dropped by the owner.
- **The command, by how the session runs** (`hub/sessions.mjs` `joinOf`). The hub board's session runs in tmux: `tmux attach -t kickflip-<route>`, left with ctrl-b d. Every other board's runs as a background session (`claude --bg`): `claude attach <short id>`, the session id's first 8 characters, left with ← (agent view) or Ctrl+Z (shell). A board with no session recorded has no command. `/exit` inside it ends the session, and the hub wakes it on the next event; the sheet says so.
- **In the board's data.** `/api/board` carries `join` `{command, tmux}` or null, read from the manifest's owner on every build, since the session id changes on a fresh start. The page's saved copy holds it, so the sheet shows the command while the server doesn't answer.
- **Where.** The board's name in the header is a button with a ▾ that opens the board menu; its row Join in terminal shows the session's state as a dot and word, and opens the join sheet (`ui-header.js` `boardMenu`, `joinSheet`; `app-header.js`). The menu's other rows (settings, repo review, triage, pause) come with T-606. A shared person's tap opens nothing: the command runs on the owner's machine.
- **States** (`ui-header.js` `joinState`): Running (green) shows the command with Copy. Asleep (grey) shows it greyed with Wake, which posts `/_hub/wake` as any tap on an asleep page does; while waking (orange) the button shows the standard spinner (`button[aria-busy]`) and no text, and once the session runs the command gets its Copy. Server not answering (red) shows the saved command with Copy and no Wake, since a wake needs the server. Not listening (red) keeps the command with Copy. No session yet (grey), also while a new board's session starts, shows no command.
