# A board pulls in open GitHub issues no task names

Owner, 11/27: a board setting pulls in open issues from its GitHub repo, so an issue opened there reaches the board without someone filing it by hand. It is a Hub settings Board default, Off, that a board can override, with three values: Off, Assigned only, All. It pulls only from the board's ticket source. Each pulled issue files as a discussing task and wakes the orchestrator to sort it. Turning it on shows the count and asks whether to take them all or only new ones from now. Linear's pull and closing the issue upstream are separate tasks.

- `pull_issues` (off | assigned | all) joins the Board defaults in `settings.json` `boardDefaults`, built in as off; board.json's key overrides it, and null drops the override. `settings set pull-issues off|assigned|all|default` writes it, as Board Settings' Overrides row and Hub settings' Board defaults do. It is a silent default: a change writes board.json and wakes no session.
- Only a board whose ticket source is GitHub and whose tasks live in one item file pulls, from its repo (`hub/issue-pull.mjs issueRepo`). A Linear board or a waves board pulls nothing.
- The issues ride the hub's GitHub poll: its one GraphQL query gains an `issues<i>` alias per pulling repo, the newest 100 open issues with their total (`hub/pr-report.mjs fetchPRs`). A board with the pull off adds nothing to the query. An issue older than the newest 100 is not pulled; the backlog count reads 100+.
- An issue is named when any task in any lane, or the Done archive, has ticket `#n` or id `GH-n` (`board/cards.mjs namedTickets`). The poll files each unnamed one, oldest first, as `<slug>/GH-<n>` with ticket `#n`, the issue's title, phase discussing, and notes linking the issue and its author, under the tickets lock, so an issue the board is creating at ready isn't pulled before its task stores it.
- Assigned only keeps the issues assigned to the owner: the ticket source's gh account, else the board's GitHub login, else the login the poll ran as.
- Each pulled task gets the thread line "Pulled in from GitHub issue #n." and an `issue-pulled {key, ticket, title, url}` event, which wakes the orchestrator. It retitles the task Conventionally with `item set`, since `item triage` refuses a task already discussing, then moves it on as any filed task.
- Turning the pull on from off asks first: `GET /api/issue-backlog` on a board, `GET /_hub/api/issue-backlog` for the Board default summed over the boards that take it, counts what would file now. Only new ones stores `pull_issues_since` as now on the board, or on each board taking the default, and an issue created before it is skipped; All drops it. `settings set pull-issues-since now|all` writes it by hand.
