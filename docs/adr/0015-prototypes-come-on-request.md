# Prototypes come only when obviously helpful or on request

A card's question links to prototypes (its `url`) only when seeing options side by side obviously helps the owner decide. Otherwise Claude builds none.

The owner can ask for them. Each item thread's reply form has an eye button beside the attach button. After a confirmation it sends a `prototype-request {key}` event. While a request has no answer, the eye reads "…" on that item, across reloads. A tap sends nothing new: it shows "Prototypes are being made" with a bump, which sends `ask-bump {id}` with the request's event id, unless that request is already the latest bump. Once the request has a later thread line, the eye can ask again. The grill form of the request is gone ([0041](0041-hub-changes-come-as-asks-not-improvement-rounds.md)).

The owning session answers by building a throwaway `prototype-<topic>.html` in the site's `public/`. It shares the board's header, whose back arrow goes one step back, or to the work item it belongs to, `./#item=<wave>%2F<id>`, when a push opened it ([0048](0048-a-questions-takes-show-inline.md)). While the card's prototype question is open, the card carries an Action needed badge linking to the page and, unless Claude is working on it, sits in In Review reading "Prototypes ready: pick a take"; once the owner picks, it returns to its own lane ([0045](0045-the-lane-follows-who-acts-next.md)). The page switches its takes with the board's `prototype-switcher.js`, loaded by a relative src after `claude.js`: a floating ‹ take › pill, ←/→ keys and `?variant=`, and with `?take=` one take alone for the questions page's frame ([0048](0048-a-questions-takes-show-inline.md)). With each prototype Claude adds an open question on its card ([0029](0029-a-card-is-grilled-through-its-own-open-questions.md)): one option per take, its id the take's key, options in take order and the recommended take tagged with `recommended: true`, with `url` set to `prototype-<topic>.html?q=<question id>`. With `?q=` the pill offers Pick this on a take that is one of the question's options; it sends at once, with the note typed above the pill, the same `owner-answer` event questions.html sends, then moves on to the next open question ([0048](0048-a-questions-takes-show-inline.md)). Once answered, the picked take reads Picked and the others offer Change pick. Waiting on you shows fitting takes in a grid, or a choice row above one full-width take when any take scrolls; its note and Send follow the take. A page opened from a thread keeps its header and take pill. The session links the page from a thread line. An ask answered with prototypes waits on the owner's pick in In Review with `board.mjs ask progress <eventId> --next <text>`, and the owner's Done moves it to Done ([0035](0035-an-ask-can-wait-in-progress-until-the-owner-marks-it-done.md)).

The owner chose on-demand prototypes, leaning towards none by default unless obviously helpful (round `site-v10`), and the pending eye with its bump (round `site-v13`). They then asked for prototypes to live on the card's Grill button as open items, picked from the switcher.
