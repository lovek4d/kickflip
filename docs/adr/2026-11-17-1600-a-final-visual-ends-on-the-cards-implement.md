# A final visual ends on the card's Implement

The owner asked that a UI change be confirmed on a visual of the final, iterated with them until they confirm it: prototypes are the first pass, and a visual refines after a pick (T-467, T-609). T-612 is the confirm loop; T-613 has a take pick lead to it.

- **A final visual is a visual brief marked final.** `item brief <key> --kind visual --final --file <draft.md>` sets `final` on the written brief (`store.mjs` `writeBrief`); `--final` on any other kind is refused. The brief rides the agent's record like any visual's, so a relaunch keeps it.
- **Its agent asks no question.** The visual brief tells a final visual's agent to place its page with `visual add <key> … --implement` (`headless.mjs` `visualBrief`), which marks the card waiting on the owner's Implement as `thread --implement` does, so its link line and the card's orange Implement are the confirm. The grill's split first had the agent post a "Build it as shown?" question with Implement its one option and a note left unchecked as a redraw; the owner dropped it before the build (T-606, 11/17): "Actually let's not use the question for implement confirmation choices after a visual, only use the tap implement next action."
- **A change is the owner's note in the thread.** It clears the mark and reaches the orchestrator as a reply wait, which briefs the next final visual. Nothing owes the redraw automatically: the orchestrator reads the note and decides the round, as for any thread message.
- **Implement is never held.** The card's own Implement builds whenever it is tapped, the visual drawn or not. `visual add --implement` on a card already staged, ready or past Todo is refused before the page is placed, as `--implement` is everywhere, and the brief has the agent place the page again unmarked. `item brief --final` is refused the same way on a card that owes no Implement (a built card, T-857), saying to brief a plain visual: its page would place unmarked and the card's next step is the orchestrator's verify, not a tap.
