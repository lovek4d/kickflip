# A sent answer is resolved in place until the page reloads

Card #307. On Waiting on you, sending an answer is the owner resolving that question. It is a plain record, separate from whatever the orchestrator does next. The work item shows that progress; the question doesn't.

- **Resolved on Send.** A question with an answer sent (`answered` or `replied`) or that Claude resolved draws as the resolved card (ui-questions.js `isSent`, `resolvedCard`). The card is locked at its pick, tinted green with its border drawn inside, carries a "✓ Resolved" badge top right and the line "Sent. Tap Resolved to reopen it." The "waiting for claude" and "claude replied" badges and the "Waiting for Claude…" line under an answer are gone.
- **In place until reload.** For the page's lifetime, view-questions.js remembers every question it has drawn in the form (`inPlace`). Once sent or resolved, such a question stays where it is. A fresh load folds a topic's sent and resolved questions under "resolved (N)". Switching topic pills isn't a reload. Send still moves on as before.
- **Reopen.** Tapping the badge asks "Reopen this question?". OK sends `question-reopen {key?, question}`, a record-only event that wakes no session. The server refuses one naming a question with no answer sent. In domain.mjs `ownerQuestion`, the newest reopen opens the question again (`state: 'open'`, `reopened: true`) while it is newer than the last answer, the last prototype request and `resolved_at`. The reopened card fills its pick and note from the last answer, so Send is ready at once. The card's thread reads "Question N was reopened" as a request line with a turn-back arrow (`MARK_ICONS['question reopened']`; a request line takes `m.mark` when its words vary). store.mjs reads reopens too, so `question add` doesn't resolve a reopened question as "Followed by".
- **Strict numbers.** A question's number is its place among its card's questions in owner.json. owner.json only appends, so a later round's questions number on after the earlier ones. The thread's answer lines read "Question N · <question>\n→ <answer>", as does a question's prototype request. The Questions page numbers each card the same way, folded ones included.
- **Blue requested card.** A question waiting on the prototype the owner asked for gets back `pr-busy`: the accent border, inset accent ring and 9% accent tint that #157 (2009180) removed when a request resolved its question. #207 brought back the `requested` state but not the tint.
- **The Questions button stays.** domain.mjs `actionButtonOf` gives `openQuestions` to any card that has had questions (`it.questions` set), Done cards included. `resolvedBy` keeps it orange only while the card's questions action stands, which a reopen restores. Otherwise it is quiet. A card that never had questions has no button.

The resolved badge used to send `reask-request` (docs/adr/2026-11-04-2001-a-resolved-question-is-read-only-and-can-be-asked-again.md). No page sends that now. The server still takes one, and the session still acts on it.
