# Boards run in the background, sleep and wake from the page, and the hub board runs in tmux

This supersedes [the hub session is a dev-time role](2026-10-31-0024-the-hub-session-is-a-dev-time-role.md), and in part [a board's session wakes when an event arrives, and live means its session runs](2026-10-30-1601-a-boards-session-wakes-when-an-event-arrives.md) on how an asleep board reads and what wakes it, [a board restarts from its row on the Hub page](2026-11-02-1736-a-board-restarts-from-its-row-on-the-hub-page.md) on which rows have Restart, [a closed board keeps its folder and can be reopened](2026-10-31-1603-a-closed-board-keeps-its-folder-and-can-be-reopened.md) on which boards can close, [a background session's prompts and questions come to the phone](2026-10-30-1516-background-sessions-prompts-come-to-the-phone.md) on which sessions get the phone hook, [the hub board files its cards as GitHub issues](2026-11-02-1611-the-hub-board-files-its-cards-as-github-issues.md) on where the hub board's GitHub repo comes from, and [kickflip join adds the current repository as a board](2026-11-03-0248-kickflip-join-adds-the-current-repository-as-a-board.md) on what `--hub` does.

Every board's session runs in the background, as the hub starts and resumes it. It idles out after about an hour and the board sleeps until the hub wakes it. A hub board is optional; kickflip runs without one. The owner asked on #67 (11/03): "What if we just go fully into background agents … and we just have the hub server itself allow you to wake an idle session with the refresh or just let it be idle and give it a um sleeping thing", then settled the grill and take A of prototype `sleep-look`.

- **Asleep reads asleep.** The sidebar keeps its word, now lowercase: asleep, in grey. The board header says asleep, in grey, where it said a red not listening (`board/public/ui-header.js` `statusLine`); a deaf board still reads a red not listening, now lowercase in the sidebar too ("asleep should be lowercase in both, and so should not listening"). Auditing every place these words appear is a separate card.
- **Waking from the page.** "Just reuse the refresh in the header. Otherwise until you interact with something on the page." The header's refresh and any other tap or send on an asleep board's page post `/_hub/wake {route}` (`board/public/app-header.js`). The hub runs its session check at once with that route asked (`hub/sessions.mjs` `checkSessions`, `resumeStep`'s `asked`), which resumes the session as for an event that landed, once per outage. The page itself sends no event. There is no Sleep control; a board sleeps only by idling out.
- **Waking reads waking….** `listenState` (`hub/boards.mjs`) has a fourth state, `waking`: the hub resumed the session this outage (`resumed_at` in resume-state.json) and no wake has failed or gone unanswered. The header reads waking… from the tap until the board listens, the sidebar reads waking… in grey, the events link passes, and no not-listening push goes. A wake that doesn't bring the board back within the comeback wait pushes as before and the board reads not listening.
- **The hub board is a foreground session in tmux.** "I think hubs should be started in a TMUX session always and be foreground. In fact, I think that's gonna be all that separates a hub is that it is a foreground session. But a hub is not required for kick flip to run." The board flagged `hub: true` (`kickflip set <route> --hub`, `kickflip join --hub`) runs its session in the foreground inside the tmux session `kickflip-<route>`, which the hub starts when it wakes or restarts that board, and `kickflip hub` starts when none runs. `kickflip hub` then attaches this terminal to it (`tmux attach-session`, or `switch-client` from inside tmux). While the tmux session runs, `kickflip hub` only attaches; a session live outside tmux is refused as before. A foreground resume keeps the session's id. Its first prompt still points it to [hub-session.md](../hub-session.md).
- **The phone hook goes to the hub board too.** "yes": the tmux session's claude gets the same flags as a background start, `BG_SETTINGS`' permission hook and auto mode included, so its prompts reach the phone while nobody is attached.
- **No other hub-flag rule.** "dash dash hub just becomes a parameter for join and all that enables us to do is have a foreground session that is joinable by … doing kick flip hub." The hub board works on its own folder as any local board ([kickflip join adds the current repository as a board](2026-11-03-0248-kickflip-join-adds-the-current-repository-as-a-board.md)): its repo is its session's folder, its GitHub repo is its entry's `github`, and Board Settings can change its repo. It can close, and it has Restart, which stops the session and resumes it in tmux. Doctor's and the fetch's skips follow `local`. The kickflip hub board's folder is kickflip's clone, so its builders still branch from that clone's local main, through the local-board path. A board whose repo is the running kickflip clone scopes its architecture review to kickflip's code, which only the hub board's flag did before. The migration that flagged `hub-orchestrator` by its route goes.
- **One migration.** The hub, as it starts, makes a hub-flagged board without `local` a local board of its session's folder, recording that folder's GitHub origin and branch as `kickflip join` does (`hub/board-repo.mjs` `migrateHubBoard`, `hub-local` in the manifest's `migrated` list).
- **tmux is a prerequisite only for a hub board.** `kickflip doctor` reports it as optional when missing, with `brew install tmux` on macOS and `sudo apt install tmux` elsewhere.

Considered:
- the hub board in the background too, as #48 first proposed: the owner chose a foreground session to type into;
- a Sleep button beside the wake: the owner wanted idle only;
- waking by sending `check-github` from the page and letting the next session check pick it up: the wake would wait for that check, and the owner asked for a direct one;
- a separate wake control in the header: the refresh is already there;
- keeping the hub board on the running clone regardless of its folder: the clone special case is what the owner asked to drop.
