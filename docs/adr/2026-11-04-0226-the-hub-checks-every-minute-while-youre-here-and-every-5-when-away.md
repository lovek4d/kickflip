# The hub checks every minute while you're here, every 5 when away

The polling windows were there to save Claude usage: each GitHub check could wake sessions, so the hub checked every 15 to 60 minutes by the time of day. A check that finds no change wakes nobody, and it costs no Claude usage. What it did cost was GitHub's budget. Each PR took one GraphQL `gh pr view` and three REST lists, so a 1-minute cadence with 30 PRs would go over GitHub's 5,000-an-hour REST limit. This replaces [the hub polls GitHub and sends pushes on one interval](2026-10-29-1639-the-hub-polls-github-and-sends-pushes-on-one-interval.md).

- **One check.** Each check fetches and pulls every board's repo, checks incoming PRs, and reads every card PR in one aliased GraphQL query, with no REST call per PR (`hub/pr-report.mjs` `fetchPRs`). The query also returns the viewer's login and the rate limit. GraphQL has no `since`, so each PR brings its last 50 comments, 50 reviews, 50 review threads of 20 comments each, and 50 check contexts, and `reportOf` filters them by time as before. A PR GitHub can't resolve leaves only its own boards unreached. A failed query reaches no board. The REST `fetchPR` stays for `board.mjs pr`. The query costs about half a point a PR, so about 50 open PRs at one check a minute stay well inside the 5,000-point hour.
- **The cadence follows presence.** Checks run every minute while the owner is present and every 5 while away (`hub/schedule.mjs` `CHECK_MINUTES`, `checkEvery`, `nextCheckAt`). Present means the Mac is in use (ioreg, as pushes already read it) or a shell page was tapped, keyed or scrolled in the last 3 minutes, on any device (`hub/presence.mjs` `ownerTracker`). A page tells the hub through `POST /_hub/presence`, at most once a minute while present and at once while away. Coming back runs one check at once and restarts the 1-minute cadence from it. Every board runs the same cadence, since even an idle board wants main fetched often.
- **Rate guard.** Below 1,000 GitHub points left (`LOW_POINTS`), checks slow to every 5 minutes while present and every 15 while away until the budget recovers. A check with no card PRs makes no query and clears the guard.
- **Every PR change wakes the board's session**, as before (`github-change`). Owner: "It would be the same as me queuing up some more messages to the session while it's working."
- **Quiet hours replace the windows.** Settings hold `quiet: {start, end, hold}` in place of `polling`, 10:00pm to 8:00am with the hold on by default. With the hold on, pushes queued inside quiet hours wait for its end. Snooze tonight ends at the start, morning at the end and monday at Monday's end. Off on weekends runs from Friday's start to Monday's end. The daily wake is one wake at the end of quiet hours (take A of the quiet-hours prototype). Old `polling` settings migrate once, from the last window's start to the first's, keeping the hold. The Quiet hours modal (`/_hub/settings/quiet`) shows the start and end, the hold, the muted hint "checks every minute while you're here, every 5 when away", and what the snoozes and wakes read. The Polling modal, `/_hub/settings/polling` and `/_hub/api/polling` are gone; `kickflip polling` became `kickflip quiet`.
- **Queued pushes go after each check.** Outside the hub, a queued push's next send reads 5 minutes on, the away cadence.
- **Lateness uses the slowest cadence.** `checked.json`'s minutes are the away cadence's (5, or 15 under the guard), and a link's grace is counted from the slowest cadence, 15 minutes, so a page nobody taps never reads late between two checks.
- **The moon.** While the owner reads away, a plain muted moon sits right of the board title (take A of the presence-moon prototype). It has no toast and shows no interval. It fades in over 150ms and out over 200ms, 80 and 100 with reduced motion, as the toasts do. The tap that brings the owner back drops it from that page at once, and the sidebar stream drops it from the rest. The sidebar data carries `away`.

Owner, round 3: "One minute when present, five minutes when away. Simple enough. Also, we should make sure to do one pull upon returning to active, if it was in the five minute interval rather than waiting for that five minute interval to end." On the moon: "Just a plain moon, no toasts, no nothing. The moon should fade in and out and it should go away once you come back to the page right away. It should use the same fading as the toasts." The decision notes are in the hub-orchestrator board's `data/polling-cadence-notes.md`.
