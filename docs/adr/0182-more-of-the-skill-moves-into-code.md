# More of the skill moves into code

The owner, on #129: "Do another round of converting from skill verbiage to hard rules in the code base." The audit (#129's notes, `audit-4-notes.md`) named each SKILL.md line a session can forget and the code that would take it over; the owner picked which to enforce. Each rule below is now a refusal or a default in `board.mjs`, and SKILL.md keeps only what the session must judge.

- **A session pushes only faults, and reminders the owner asked for.** `board.mjs push` refuses any `--kind` but `fault` and `reminder`: the board server pushes every Action needed ([0133](0133-the-board-records-what-it-knows-and-commands-make-the-rule-calls.md)) and the hub a session's prompt, so a session's `action` push could only double one under a tag nothing drops. `reminder` is a new push kind for a push the owner asked for in words, such as "push me when everything is done" (the owner, on #129: "it should also allow an explicit reminder such as this"); it reaches the phone as a fault does. A trigger that sends one when the board goes idle is a card of its own. SKILL.md's tag, rewrite-on-reply, `--now` and queued guidance for sessions goes; `node $KF push` keeps every kind for the hub's own callers.
- **A build makes its own worktree.** A build start (`--kind build`, `claude` or `codex`) for a card's main record, on a site the manifest lists as a board, makes the card's worktree when the record keeps none, as `--worktree` does ([0064](0064-every-builder-works-in-a-worktree.md), [0173](0173-a-build-remakes-a-leftover-worktree-that-holds-no-work.md)). A record taken up or resumed keeps its worktree, and a build started again keeps the one its last record left while it is still there, so a resumed builder isn't refused over its own commits. An `--agent` record and a site with no manifest entry make none, as before.
- **Calls hand back through `builder done`.** On a record with unverified judgment calls, `builder done` sets the card to checking with Next "Answer the builder's questions" when any call starts "Question:", else "Verify the builder's judgment calls", and refuses a `--next` of its own ([0155](0155-a-builder-records-its-judgment-calls-and-the-session-verifies-them.md)).
- **A filed card has a state.** `item set --from-ask` refuses without `--state` while the card has none ([0154](0154-a-new-card-is-ready-grilling-or-prototyping.md)).
- **A reopened card closes on the owner's Done.** `item set --status done` refuses a done card the owner messaged since it closed ([0128](0128-a-message-or-question-on-a-done-card-reopens-it.md)). The owner's Done tap goes through the board server, which this check doesn't touch, and `land` still closes a card it lands; the owner step after a land is #127's.
- **Claude's GitHub posts go through the board.** `board.mjs pr comment <pr> --body` and `pr reply <pr> <comment id> --body` post on the board repo's PR through gh, as the board's github-login, adding "🤖 " and the `<!-- claude-bridge -->` marker that `pr` reads as Claude's own (`hub/pr-report.mjs` `postToPR`). Words already carrying either are refused.

SKILL.md also drops lines that only describe what code does: the refusal and exit-code sentences, the card-unbump, card-hold, card-done and queued-build "needs no action" notes, the 80-character detail limit, land's step list and `question add`'s url refusals.

Considered and left:

- **A watcher that streams under the Monitor tool.** A Monitor is killed after at most 30 minutes, and a live Monitor counts as working, so a board's session would never idle out and sleep ([0061](0061-a-boards-session-wakes-when-an-event-arrives.md)) and would wake every 30 minutes to re-arm it. The watcher still exits on each event and is relaunched.
- **Blocking "above", "below" and "this session" in messages.** The owner: such a pointer can mean something earlier in the card's own thread. SKILL.md says a pointer must make sense in that thread instead.
- **Pushing main after every land** goes to #130's board permissions.
