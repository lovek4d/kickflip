# kickflip join adds the current repository as a board

This supersedes in part [0087](0087-a-page-joins-without-a-session.md), on how a join names its site; [0113](0113-the-hub-trusts-the-clones-it-makes.md), on which folders the hub marks trusted; [0073](0073-a-new-board-chooses-a-repo-and-branch.md), on where a board without a GitHub repo builds; and [0069](0069-the-hub-starts-a-new-boards-session.md), on the join flags New board's session gets.

The owner asked on #48: "just make it a short command that interactively joins the current repository to the running hub and if the hub is not running it tells you to do kick flip install", and settled the shape in a grill on #53 (11/03). New board in the app stays clone-from-git; this is the path for a repo already on the host.

- **Bare `kickflip join`.** Run in a git repo's folder, or any folder inside it, it asks one thing, the board name, defaulting to the folder's name with anything but letters and digits read as spaces. The name takes letters, digits and spaces ("alpha numeric and spaces and just hyphenate it to use as the route"), and the route is the name lowercased with dashes for spaces. With no terminal to ask in, `--name` is needed, so a script or test never waits on a prompt. It always makes a board, from the board template, with its own cards in `data/wave.json`, as a New board start does.
- **Refusals.** A folder outside git is refused (exit 2); a repo with no origin joins. While the hub isn't running, join says to run `kickflip install` and makes nothing. A taken route is refused, and asked again in a terminal.
- **Its repo.** The folder's origin, when it is on GitHub, is recorded as `github`, and its checked-out branch as `branch`. The entry is marked `local: true`: like the hub board, its builders branch from the folder's local `main` and `land` fast-forwards that `main`, and the hub fetches nothing for it. Pulling the remote is follow-up work (owner: "adding some git pull functionality either automatic or by clicking next to the Master Serve card"). Board Settings' Change repo moves a local board onto a shared clone and clears the mark.
- **Trust.** Running join in the folder is the owner's consent to Claude Code's workspace trust for it, as the New board tap is for a clone. Join marks the git root trusted (`hub/trust.mjs` `trustFolder`) before anything else is written, and makes nothing when the mark fails. `start` still marks only the hub's own clones; a joined folder keeps the mark join gave it.
- **The session.** Join records the folder as the board's owner folder and starts its session in the background as `kickflip start` does, its first prompt `/kickflip --name '<board name>' --template board --items data/wave.json`. With `--hub` ("Background session unless you get a dash dash hub, I guess"), it flags the board as the hub board and opens its session in this terminal as `kickflip hub` does. A start that fails leaves the board made, and says to run join again.
- **A folder that already has a board.** When a board's recorded folder is this one, join names it and asks to restart its session: the Hub page's Restart ([0121](0121-a-board-restarts-from-its-row-on-the-hub-page.md)), `kickflip hub` for the hub board, or a fresh start when none is recorded. With no terminal it only names the board.
- **One name flag.** Every other join keeps its flagged form, with `--name "<name>"` in place of the route argument and `--title` ("Should just be one flag for dash dash name"). The name gives the title and the route, its other characters becoming dashes as New board's names do (`hub/routes.mjs` `routeFromName`), so a New board name with punctuation still joins its own route. A name that is the route itself keeps the site's title, so a board whose title hyphenates elsewhere rejoins by its route; the hub's resume and start prompts, `kickflip hub`'s and import's printed line name a board that way (`joinName`). A route argument or `--title` is refused with the line to use instead.
- **Plain pages** name their route the same way, `kickflip join --name "<name>" --port <n>` or `--dir <folder>`. A rejoin passes `--port`, `--dir` or `--cmd` again, since a join with none of them and no session is the folder join above.
- **No fallback to kickflip's clone.** A board with neither a GitHub repo nor a plain git remote builds from its own folder's local main, as a local board does, and `land` with no recorded worktree lands into that folder (`board/worktree.mjs` `builderRepo`, `hub/boards.mjs` `buildsLocally`). A board with no folder recorded is refused rather than built in the wrong repo. Only the hub board uses kickflip's clone, and only `builder start` and `land` without `--site` still default to it.
- **New board sheet.** One line under the repo field reads "A repo already on the host running Kickflip? Run `kickflip join` in its folder.", with no wording that assumes a Mac.

Considered:
- keeping the route argument beside `--name`, which leaves two names that can disagree;
- a Starting row for a joined folder, as New board makes: Retry there re-clones from GitHub, and a board that exists at once can be restarted by running join again;
- building a joined board from `origin/<branch>` as a shared clone's board does: the folder is the owner's own checkout, and the owner chose local main like the hub board.
