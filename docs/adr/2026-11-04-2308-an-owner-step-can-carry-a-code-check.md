# An owner step can carry a code check

A card waiting on its owner step ([a card whose code landed stays in review while an owner step remains](2026-11-04-0158-a-card-whose-code-landed-stays-in-review-while-an-owner-step-remains.md)) closed only on the owner's Done, even when code could tell the step was done. #12 waited on three owner steps (an npm trusted publisher, Actions on, a `v*` tag), all proved by one fact: a newer version on npm.

- **One check, on the final evidence.** `--check "<name> <args>"` goes beside `--owner-step` on `builder done` and `land`, and is refused without it. `item set <key> --check` adds or changes the check on a card already waiting on its step, and `--check ""` removes it. The check is stored as the item's `owner_check` `{check, since}`, `since` being when it was attached. It is deleted when the step is.
- **Named checks, never a shell command** (`shared/owner-check.mjs`). The kinds are `tag <owner/repo> <pattern>` (`git ls-remote --tags`), `npm <package> <version-or-range>` (`npm view`), `run <owner/repo> <workflow>` (a successful `gh run list` run since `since`), `gh <owner/repo> <api-path> <field>=<value>` (a `gh api` GET under `repos/<owner/repo>`) and `url <address> [<status> | <text>]`. For `url`, a three-digit word is the status, and any other text must be in a 200 body. Each runs as an argv call or a fetch, with no shell. An unknown name or bad arguments are refused when the check is attached. A shell string would have the hub run, every minute and with the owner's credentials, text a builder wrote from PR and issue text that a comment can steer. Nobody would review it, and a non-zero exit can't tell "not yet" from "broken".
- **The poll runs it** (`hub/owner-checks.mjs`, from `hub/github.mjs` `checkGitHub`), on the hub's cadence and rate guard, for each card whose status is done or merged with an owner step and an unbroken check. Each check runs once however many boards show the card. A card whose code hasn't landed isn't checked, so a release that predates the land can't close it.
- **On pass it closes at once**, as the owner's Done does (`board/store.mjs` `passOwnerCheck`). The step clears, a merged card stays merged, the ticket moves, and the thread reads "Check passed: <what it found>. Closed." No push is sent.
- **"Not yet" does nothing.** A check that ran and found nothing is the normal waiting state.
- **"Can't run" wakes the session.** An error (no such repo or package, no auth, a bad path, an unreachable address) counts in `github-state.json` `ownerChecks`. Three in a row mark the check `broken` (`breakOwnerCheck`): it stops running, the card reads "Check can't run: <error>", a thread line says so, and `owner-check-broken {key, check, error}` wakes the session to fix it with `item set --check`. Setting the check again clears the mark. Like `github-change`, the event waits while usage is paused. The owner's Done always closes the card, check or not.
- **How it looks.** Under the step's Next the card reads "Checks: <what it waits for>" (`board/public/ui-cards.js`), for example "Checks: kickflip@0.3.* on npm".

Owner (11/04, on #127): "if there is some way to check with code, then it can attach a code watcher and that can flag the card as done". Owner answers on #196: named checks plus a URL check; close it at once; wake the session to fix a broken check; one check, on the final evidence.
