# A button without a text box posts a keyed status line, and a bare Implement readies the card itself

The owner on #367 (11/06): "Implement should not also send quick build in the thread. Rule: any buttons without a text box associated with them should send a status line only in the thread, and the skill should outline keys that each of those status lines mean to inform the orchestrator. So something like command: implement “Implementation requested” with icon defined, or command: prototype “Prototype requested” with icon defined, and then that line is read in by the orchestrator if it doesn't have a clearly defined next step. Honestly implement should have a mark as ready mechanical next step so it just goes to in progress at that point with whatever is on the card, and just add the “Implementation requested” status line only"

- **One table of keys.** `domain.mjs` `COMMANDS` maps each key to its words: `implement` "Implementation requested", `prototype` "Prototype requested", `grill` "Grill requested", `visual` "Visual requested", `reask` "Re-ask requested", `hold` "Held" (or "Held until <time>"), `resume` "Resumed", `done` "Marked done". `ui.js` `MARK_ICONS` holds each one's icon, and the icon test of [every thread status line carries an icon](2026-11-07-0600-every-thread-status-line-carries-an-icon.md) covers every key. SKILL.md lists what each key means for the orchestrator.
- **Each such tap is a status line, never a message.** A bare Grill, Prototype, Visual or re-ask is a request entry from its event, as before, now carrying `command`. A bare Implement, a Hold, a Resume and a Done are thread-file lines with `command` set (`store.mjs` `appendThread`), which the thread draws as request lines (`kind: 'command'`); a Hold's line names its mark, as its words vary. Hold, Resume and Done were the owner's messages ("Held.", "Resumed.", "Marked done."). A New task sent with Quick build reads "Implementation requested" under the ask, in place of "quick build: no grill". A Full person's name shows on any request line.
- **A bare Implement is mechanical.** On a Todo or ready card the board server writes the "Implementation requested" line, marks the card ready as it is (dropping `unfiled`, skipping item set's notes and open-question checks) and starts the build as the Build tap does, or bumps it while a dep blocks it (`store.mjs` `implementAsIs`). It records no event and leaves nothing on the orchestrator's list. One the tap refuses gets back the state it had, with the refusal line. The page sends the bare message; the "Quick build" text (#302's call 4) is gone.
- **An Implement with text stages the card**, as [staging, then ready](2026-11-07-0700-staging-then-ready.md) has it; a bare one on a card not ready no longer stages it, but readies it as above.

Considered: keeping the empty-Implement path through the orchestrator (the `implement` wait, folding "Quick build" into the notes): the owner wants it to move at once with what the card already holds. Changing the "Quick build" label in the New task sheet is #356's.
