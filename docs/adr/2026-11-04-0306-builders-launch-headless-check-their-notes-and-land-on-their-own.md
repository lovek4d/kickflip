# Builders launch headless, check their notes, and land on their own

On a board with `headless_builders` on (`settings set headless-builders on`, or Board settings' "Builders launch headless"), the board server launches each build itself, and the session only answers builders' asks and verifies their judgment calls. The setting is off by default, so every other board keeps the orchestrator path: `card-build` and `card-pull` wake the session, which briefs and launches the builder and lands what it hands back. This builds the rest of #139's card (direct-builders-notes.md) beside [a builder asks the orchestrator mid-build](2026-11-04-0247-a-builder-asks-the-orchestrator-mid-build.md).

**Ready means a builder can start from the card alone.** `item set --state ready` refuses a card without a size, without a notes file, or whose notes file doesn't name the id of every question on the card the owner answered (`board/store.mjs` `checkNotesComplete`). The open-question refusal stays ahead of these checks. A board without the setting keeps ready as it was, since its session still writes each brief.

**The hub launches the builder.** The Implement tap, a queued start and Auto implement's pull all start the build in the board server as the tap already did (`startTappedBuild`; a pull marks its record `dispatched: 'hub'`), then launch `claude -p <brief> --permission-mode auto --model <pick>` in the card's worktree, detached, its output in `~/.claude/kickflip/logs/builder-<id>-<time>.log`, with a thread line naming the model, worktree and log (`board/headless.mjs` `launchBuilder`). No `card-build` or `card-pull` goes to the session. The brief is built from the card: its notes file, the hub's and board's rules, and the board CLI's builder steps (start, progress, ask, call, done, land). A codex pick, or a launch that fails, still sends `card-build`, so the session launches it.

**Limits are the board's existing ones.** Launches obey Maximum parallel implementers, which already counts cards building and in Orchestrator review, and the usage pause, which refuses a start and holds the Auto jobs. The notes recalled a load of 40 with seven parallel builds but settled no other limit, so none is added; Maximum parallel implementers is where to turn it down.

**A builder lands its own work.** With no judgment calls recorded, the brief has it run `board.mjs land`, which rebases onto the board's branch, reruns the full suite and fast-forwards; on a conflict, land undoes its rebase and names the files, and the builder rebases with `git -c core.commentChar=';' rebase`, resolves them, reruns the tests and lands again. Landing never goes to the orchestrator. A build with calls hands back to checking as before. Once the session marks them verified and the card has no open question (a deferred ask waits for the owner's answer), the server launches a headless lander for it, once per verification, tracked in `data/landers.json` (`store.mjs` `landable`). The lander's brief carries the owner's answers to the deferred asks, so it changes the build where an answer asks for it, then lands as a builder does.

The owner, on `gh139-launch`, `gh139-notes` and `gh139-land-fails`: headless, "check", and "Could we have it so that the builder has to have the commits fast forward merged on top of main? And so then the builder just has to handle conflicts and we can still keep everything automatic above that. The orchestrator never has to be bothered."

Considered:
- the check, launch and land on every board: boards whose session writes each brief would refuse ready on cards their session can build from its thread;
- the session landing a build once it verified its calls: that sends conflicts back to the orchestrator, which the owner ruled out;
- a smaller parallel cap for headless builders: the notes left the number open, and Maximum parallel implementers already caps them;
- launching codex headless too: its CLI takes other flags and a brief that this change doesn't need to settle, so the session still launches it.

Superseded in part by [lands and builders run only the tests a change affects](2026-11-12-2104-lands-and-builders-run-only-the-tests-a-change-affects.md): a land and a builder run the test files the change affects, not the full suite.
