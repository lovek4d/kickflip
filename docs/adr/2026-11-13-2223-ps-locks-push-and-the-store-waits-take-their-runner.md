# ps, locks, push and the store's waits take their runner

Card #659, fix task F6 of docs/test-determinism-audit.md, under docs/adr/2026-11-13-2130-the-main-suite-holds-no-new-timer-waits.md. The tests of these modules waited on a real ps under its 3 s timeout, on a lock's real 100 ms polls and 10 s deadline, on a push sent to a device on a port, and on the CLI's real 2 s polls. Each module now takes the thing it ran as an option, its default the one it ran before, so shipped behaviour is the same and a test answers in process.

- **ps.** hub/live.mjs `processStarts`, `liveSessions` and `parentOf` take `{ps}`, as do board/headless.mjs `stopRuns` and board/stop.mjs's stops (a runner `{ps, grace}`, which board.mjs `main` passes from its options). `fakePs(rows)` in shared/test-helpers.mjs answers from a table of processes. orchestrator-stops runs its CLI stops in process with a grace that never ends, so a stop returns once what it stopped is gone, and the test asserts that at once instead of polling. stop.mjs reads a land's process group through live.mjs `ps` too.
- **A stalled ps gives no answer at once.** `stallingPs`'s stall makes the stand-in kill itself instead of sleeping past a shortened timeout, since live.mjs `ps()` reads a timeout and a killed ps alike, as no answer. `KICKFLIP_PS_TIMEOUT_MS`, which existed only to shorten that timeout, is gone.
- **Locks.** `withFileLock` takes `now` and `wait` for its deadline and its polls. Each time it waits for a held lock it emits `'wait'` with the file on `lockWaits`, a module-level emitter, so a test knows a writer waits at the lock (`lockWaited(file)`), where it slept 250–300 ms before. The emitter is module-level, not a per-call option, because the waits a test watches are inside `moveCard`, `withSessionLock` and `withManifestLock`, none of which take lock options. Its default timeout is `KICKFLIP_LOCK_TIMEOUT_MS`, else 10 s; the tests where processes contend for one lock, which is their point, set it to Infinity, so load decides how long a waiter waits, never whether it fails.
- **Push.** hub/push.mjs reads its home per call (an argument, `os.homedir()` by default) and `deliver` and `flushQueue` take `{home, fetch}`. push.test runs in process against `fakeDevice`, a device reached through its own fetch. Tests that push through board.mjs still spawn it, since store.mjs `sendPush` runs `kickflip push`; the server's push seam (F1) is where that goes.
- **The store's waits.** `store.listAsks` and `store.waitHelper` take `now` for their deadline; their tests run in process under `t.mock.timers`, ticking from the moment the loop is about to sleep.

hub/boards.mjs `watcherRunning`, `isListening` and `listenState` take `{ps}` too, for the watcher's command line. The Stop hook still runs as a script in its test, since hub/boards.mjs fixes its paths from HOME at import; its watcher check is tested in process on fakePs instead.
