# A closed board keeps its folder and can be reopened

Closing a board stops its work here while keeping what the owner may want to return to. The owner picked take A of `prototype-close-board.html`, keeping the folder and warning about active work, and added a typed-name confirmation. Deleting cards, threads and notes would make closing irreversible; refusing while a PR or builder is open would make the owner finish work they want to stop.

- **Confirmation.** Board Settings has a Close board row. Its sheet names the session, server and sidebar row that stop, says the folder stays, and lists open PRs and running builder records as a warning. Close stays disabled until the exact board title is typed; the hub and CLI check that title too.
- **Session and builders.** A live background session stops through `claude stop <id>`, which keeps the conversation for resume. A live terminal session receives SIGTERM only after its recorded PID and a valid process start time match a fresh process lookup; an unverifiable identity is refused. Close waits for the recorded process to stop, and a failed stop leaves the board open. Close, start and resume share a per-route session lock, so an in-flight wake finishes before Close stops that session. The board store closes each open builder record with a note in the record and card thread, clearing its building or fixing status when the last record ends. Closed builders remain finished when the board reopens.
- **Folder and PRs.** The site folder, cards, threads and notes stay on this Mac. PRs stay open on GitHub. The site leaves the manifest's active `sites`, so the hub stops its server, drops its sidebar row and stops polling its PRs or waking its session. Other boards showing the same PR may still poll it.
- **Closed entries.** The manifest keeps `closed[route] = {site, title, cursor, closed_at}`. `site` is the full former entry, including its owner, folder, port, command, icon, colour and join time. `cursor` keeps the watcher position read before the session is stopped; missing counts start at zero so pending events remain deliverable. Existing manifest readers use `sites` and `starting`; only the closed list and reopen path read closed entries, and port allocation reserves their ports. Keeping this in the manifest makes the move atomic under the same lock as join and leave, with no second file to reconcile. Closed routes stay reserved against join and New board.
- **Reopen.** The hub page’s expandable Closed boards row lists them with Reopen. The hub endpoint and `web-ts reopen <route>` restore the saved entry and resume through `hub/sessions.mjs`, keeping its recorded folder and model and recording any replacement session id as usual ([the hub resumes a session only when nothing runs it](2026-10-29-1811-the-hub-resumes-a-session-only-when-nothing-runs-it.md)). The session lock covers restoration, resume and any rollback, so a queued wake cannot launch during a failed reopen. The saved cursor is restored before launching and passed through the resume to any replacement session ID, rewinding advances the old watcher made while the board was closed. This may replay an event already delivered near Close. The folder, session and repo must still exist; a failed resume puts an unchanged entry back in Closed boards for retry.
- **Hub board.** The board flagged `hub: true` cannot be closed, regardless of its route ([the hub session is a dev-time role](2026-10-31-0024-the-hub-session-is-a-dev-time-role.md)). The Close board row is disabled with a reason, and both the endpoint and CLI refuse it. Close also refuses a session recorded by another active board and names that board, so shared ownership cannot stop the hub board or any other board.
- **Response and access.** Close posts directly to `/_hub/close-board`, so it does not depend on the board server it stops. Reconciliation waits until that response is flushed before stopping the site's server; the page then opens the hub. Close and Reopen share the browser cross-site guard and JSON requirement of the other hub writes ([the hub starts a new board's session itself](2026-10-31-0137-the-hub-starts-a-new-boards-session.md)).

Considered:
- Deleting the site folder with a typed confirmation: permanent loss for an action the owner may want to undo.
- Refusing while PRs or builders remain: prevents stopping an unfinished board.
- A separate closed-boards file: requires coordinating two writes for a single move.

Board Settings opens as a modal, and its confirmation points to Hub → Closed boards ([hub settings expand in place and board settings open in a modal](2026-10-31-1721-hub-settings-expand-in-place-and-board-settings-open-in-a-modal.md)).
