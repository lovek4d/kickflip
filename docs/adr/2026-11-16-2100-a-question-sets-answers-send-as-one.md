# A question set's answers send as one

Supersedes, for the questions sheet's Send, the per-question sending of [Each answered question shows at once as sending](2026-11-16-0500-each-answered-question-shows-at-once-as-sending.md): its outbox, footers, Retry and X stay, but a Send is now one outbox entry and one request again, as [Send records every ready answer in one request, all or none](2026-11-03-1519-send-records-every-ready-answer-in-one-request.md) had it.

The owner on T-537: "Questions should send all together, why are they sending one by one?" Each answer went out as its own `owner-answers` about half a second apart, so a six-question Send landed as six events, each waking the orchestrator and each its own "sending…" bubble in the thread. Then: "now that the questions are in a modal, the modal should dismiss on send being clicked, regardless of whether there are unanswered questions, the user can return for them later. Clicking send should close the modal and place the message in the thread as sending…", and "X should just dismiss it. Modal if reopened e.g. from questions should have the values that were input before the send still anyway."

- **One Send, one set.** Send puts every answered question of the sheet's topic in the answer outbox as one entry, `{sendId, topic, key?, ts, answers, text, uploads?}`, and sends it as one `owner-answers` whose answers each carry the set's `sendId`. The board records them in one write (`server.mjs` `recordAnswers`), so their events share a ts and `domain.mjs` `foldSubmits` folds them into one thread message carrying that `sendId`.
- **Send closes the sheet.** It closes at once, whatever is left unanswered. Send is on once any question has a pick or a note; only those go, and the rest stay open on the card and the ? page with their picks and notes.
- **One message in the thread.** A card's set draws as one line, its answers numbered as the board words them, joined as `foldSubmits` joins them, with one footer: sending…, then waiting… once the board has it, until the board's own line takes its place. Its files show as tiles from each answer's own box (`send:<sendId>:<question id>`), and each answer sends with its own files once every one is up.
- **Not sent: one Retry, one X.** A set the board answers with an error reads not sent with one Retry and one X. Retry sends the whole set again under its `sendId`; X only dismisses the message, its questions open again with their picks, notes and files, since drafts stay until the board has the set. The sheet, opened again from the card or the ? page, shows a set still going or not sent read-only per question, with the same footer, Retry and X.
- **A set that wasn't sent is back on the ? page.** Waiting on you's row and the badge leave out the questions of a set on its way, as before; a failed set's questions count again and the row reads "Not sent" in red (AGENTS.md Colour priority), since with the sheet closed it is the way back to Retry for a topic with no card.
- **The outbox key moved.** Entries live under `answer-sets` in place of `answer-outbox`; whatever an older page left under the old key is not sent, its questions open with their drafts.

The ? page's row while a set is sending still drops out rather than reading "sending…" as the visual drew it: the notes' build asks for the thread's one message, and the row's count already follows the outbox.
