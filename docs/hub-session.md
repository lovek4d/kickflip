# Hub session

You own the hub board, the one board whose manifest entry has `hub: true` (`kickflip set <route> --hub`, `kickflip join --hub`). That flag only means your session runs in the foreground, in the tmux session `kickflip-<route>` the hub starts, and `kickflip hub` attaches the owner's terminal to it; every other board's session runs in the background, and kickflip runs without a hub board ([boards run in the background, sleep and wake from the page, and the hub board runs in tmux](adr/2026-11-03-0313-boards-run-in-the-background-and-the-hub-board-in-tmux.md)). Your board is otherwise a local board of its folder: builders branch from that folder's default branch and land there ([a local board builds and lands on its default branch](adr/2026-11-03-1851-a-local-board-builds-and-lands-on-its-default-branch.md)). Your permission prompts also reach the owner's phone. Keep new features independent of this session.

- Rejoin the board by its name, `join --name '<board name>'` as your prompt gives it, with your current session id, relaunch its watcher and record how to restart it, following [Steps 1, 3, 5 and 6](../SKILL.md#steps). The owner makes a hub board from a repo folder with `kickflip join --hub` ([kickflip join adds the current repository as a board](adr/2026-11-03-0248-kickflip-join-adds-the-current-repository-as-a-board.md)).
- Sort the hub board's asks and answer what reaches you using [Board template](../SKILL.md#reference).
- Start and resume board sessions with `kickflip start` and `kickflip resume`, following [Board sessions](../SKILL.md#reference). Check `kickflip sessions` before acting; a live session already has a process.
- Relay between boards: check which board owns the work, move asks with the owner's choice as [Board template](../SKILL.md#reference) describes, and carry relevant results back to the requesting card. Put decisions for the owner on the card as open questions; the owner answers background sessions' pending prompts in the app, as [Board sessions](../SKILL.md#reference) describes.
- Edit the skill through builders in worktrees, each finishing its own card with `board.mjs builder done --text` (your `builder verified` finishes a handed-back one), following [Board template](../SKILL.md#reference) and [every builder works in a worktree, and the hub's own fault shows once](adr/2026-10-30-1654-every-builder-works-in-a-worktree.md). Keep long builds, investigations, checks and lands in background agents or tasks so you can keep answering board events.

The hub server owns card and main builds and serves through the repo’s fixed `.kickflip/build` ([a board's build script serves or builds each card and main](adr/2026-11-01-1846-a-boards-build-script-serves-or-builds-each-card-and-main.md)). Keep the script working in kickflip’s main and each card branch; file broken build steps as a card. Main always rebuilds after a merge. Auto-build cards, off by default, controls only card builds after new heads. A session starts a card run only when the owner asks in words, with `board.mjs --site <route> build <key> --asked "<the owner's words>"` ([only the owner or Auto-build starts a card run](adr/2026-11-02-1806-only-the-owner-or-auto-build-starts-a-card-run.md)); the server writes `data/try.json` and logs, without builder records or a session rebuild on GitHub head changes.
